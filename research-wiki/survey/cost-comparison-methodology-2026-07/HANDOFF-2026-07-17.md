## 1. 진단 — 문제 분류 (오늘 07-17 기준으로 재조정)

| 항목 | 성격 | 오늘 상태 |
|---|---|---|
| **C6** loss-heur ~1.7× 과대측정 | **진짜 코드 결함** (경쟁 baseline을 느리게 → 우리에 유리한 왜곡) | ✅ 코드 fix(재측정 대기) |
| **C1** Ripple 회계 범주혼합 | 구조적 예외(from-logs화 불가) | 논문서 "reported separately" 부분처리; 2블록/overhead%로 완성 예정 |
| **C3** fp32 배수 | 이미 실측(microbench), 논문만 stale | ✅ 논문 caption 교체 |
| **C4/C5** baseline=우리 재구현 / 원논문과 상이 | 서술(각주) | ✅ 논문 provenance 문단 추가 |
| **C2** FLDetector/STD-DAGMM CPU | 서술(device 열) — **tab:cost엔 해당 없음**(탐지 표 소관) | 탐지 표에서 별도 처리 |
| **C7** 학습시간·GPU-hours·peak 미기록 | 계측 갭 | ✅ §15.1/15.3 코드; 채우기는 다음 런 |

핵심 통찰: **op-count(방법별 per-round forward/grad/HVP)는 하드웨어·정밀도·재구현과 무관**하므로,
이 축 하나로 C2·C3·C4·C5를 통째로 우회한다. 그리고 `op-count × microbench per-op = 측정 wall-clock`이
**1–2% 내로 재현**되어(아래 §4) 카운트가 곧 비용 주장이 된다.

## 3. 다음 세션이 할 일 (원격 DGX 필요)

### 3.1 loss-heur canonical 재측정  ← C6 마무리
- fix된 코드로 **silo·anchor 셀 재실행** 후 loss-heur runtime을 읽어 `tab:cost` 갱신.
- **예측(op-count×per-op, 착지 목표)**: silo `60 fwd → ~96s`(현 표 170), anchor `180 fwd → ~656s`(현 표 1093).
  device 열은 loss-heur이 `---`라 무관.
- φ 불변이므로 다른 방법·fidelity는 건드릴 필요 없음. **loss-heur runtime 셀만 교체**.

### 3.2 device-cohort 학습시간 실측  ← end-to-end/overhead% device 열
- phase2_matrix에 `client-training` phase 계측을 넣었으므로 **다음 device100 런이 `timing.json`에 자동 기록**.
  (또는 device100 학습만 1회 = cheap.) 이 값이 tab:cost 2블록의 device overhead% 채움.
- silo=**409.9s**(acct 3-seed), anchor=**~1,888s**(track_d `t_vanilla`, e85df6e)는 이미 有.

### 3.3 나머지 3러너 timing 배선  ← 계측 일관성 (저위험, 로컬 가능)
- `phase2_matrix.py` 패턴 복제: ① `from flirds.timing import PhaseTimer` ② `pt = PhaseTimer(device, n_gpus=int(os.environ.get("N_GPUS","1")))`
  ③ 궤적 생성 `with pt.phase("client-training"):` ④ valuation `with pt.phase("valuation"):` ⑤ `rl.save_timing(pt.to_timing())`.
- ⚠️ `track_c1`(`t_traj`)·`track_d`(`t_vanilla`)는 **이미 궤적 시간을 잼** → 새로 감싸는 대신
  `pt.record("client-training", t_traj)`로 넣어도 됨(중복측정 회피). `phase1_baseline_compare`는 미측정이라 감싸기.

### 3.4 tab:cost end-to-end/overhead% 2블록 완성  ← C1 최종 해소 (Yonghee 결정 #1)
- 현재 `\pending` 표시됨. valuation-only(주) + end-to-end(Ripple·(a)) 2블록 or 단일표+각주.
- **재실행 불필요**: end-to-end = 공유학습 + valuation(둘 다 有, device 학습시간만 §3.2로 채우면 됨).
- Ripple valuation-only 환산치는 ripple 분리계측(항목2, 별도) 대기 — 없으면 각주로 "end-to-end만" 유지.

## 4. 다음 세션이 알아야 할 핵심 수치

**op-count per-round 공식** (|P_r|=라운드 참여수; `op_counts.py`가 재생성):
- Flirds = **1 HVP**/round (jvp-of-grad가 g와 HΔW 동시) + |P_r| dot
- Flirds-1st / FedIF = **1 val-grad**/round
- loss-heur(fixed) = **1+|P_r|** fwd/round  (pre-fix: 2|P_r|)
- Fed-LOO = **2+|P_r|** fwd/round
- ShapleyFL / Banzhaf / (b)oracle = **2^|P_r|** fwd/round
- FedSV = perm-MC `n_perm=max(30,2|P_r|)`, distinct fwd ≤ min(2^|P_r|, n_perm·|P_r|), cache+TMC-trunc 감소
- GTG = guided-trunc MC ≤ max(30, 0.8·2^|P_r|) perm, distinct fwd ≤ 2^|P_r|
- ComFedSV = `M=max(10,⌈N ln N⌉)` perm, fwd = R·(1+관측 coalition) + CPU ALS

**microbench per-op (fp32, val=100, B200; `microbench/summary.json`, 커밋 b694f07)**:
forward 1.60s / HVP 10.36s / **HVP÷fwd=6.47**. 배수 fp32/bf16: fwd 5.33·HVP 4.09·GEMM 22.68.

**교차검증 (silo N5R10, 로컬 canon `runs/phase2_matrix/rundirs/1B_silo5_noisy/metrics.json`)**:
| 방법 | op-count 예측 | 로컬 실측 |
|---|---|---|
| Flirds | 10 HVP × 10.36 = **104s** | 104.3s |
| (b)oracle | 320 fwd × 1.60 = **512s** | 518.2s |
| loss-heur(fixed) | 60 fwd × 1.60 = **96s** | 160.7×0.6 = 96.4 |

**공유 학습시간**: silo 409.9s(acct 3-seed) · anchor ~1,888s(e85df6e) · device=**공백**(§3.2).
