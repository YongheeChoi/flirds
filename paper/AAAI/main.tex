\begin{abstract}
Client contribution valuation in federated learning (FL) measures how each
participant's update improves a shared model. The Shapley value provides
principled attribution within a specified cooperative game, but exact
computation requires exponentially many coalition evaluations. Existing
approximations reduce this cost through sampling and truncation yet still
repeatedly evaluate coalition models. Cheaper surrogates and influence scores
may instead target different utilities or weighting schemes rather than the
exact Shapley value of an explicit game. Efficient client valuation must
therefore state clearly what it approximates and how to interpret its error.
We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator. Flirds treats the updates actually
received by the server as players and holds the round's server aggregation
weights fixed across all coalitions, so the grand coalition exactly
reproduces the update performed by the server. We use the exact in-run Shapley
value obtained by exhaustive enumeration as the reference and extend the
Taylor calculation of In-Run Data Shapley (IRDS) from samples to client
updates, computing the Shapley value of a second-order surrogate game in
closed form. \jwjung{We use the exact in-run Shapley value obtained by exhaustive coalition enumeration as our reference and develop an efficient client-level estimator by adapting the second-order Taylor Shapley calculation of In-Run Data Shapley (IRDS) from sample attribution to weighted client updates.} This replaces exponentially many coalition evaluations with one
server-side Hessian-vector product per round and one inner product per
participant. Because the reference and estimator target the same game, their
difference isolates Taylor truncation rather than game-definition mismatch or
Shapley sampling error. \jwjung{reference가 구체적으로 뭘 말하는지 언급하는 게 나을 것 같습니다. ex) Flirds differs from the exact in-run Shapley only by replacing the round utility with its second-order Taylor approximation. \section{Introduction}
\label{sec:intro}

Federated learning (FL) enables clients to train a shared model without
exchanging their raw data \citep{mcmahan2016federated}. In each round, the
server collects updates from the participating clients and aggregates them to
improve the model. The aggregate alone, however, does not reveal how much each
client contributed to that improvement. Such contribution estimates can
support not only participant compensation, but also data-quality management,
free-rider detection, client selection, and debugging of the training process.
The Shapley value from cooperative game theory has therefore been widely used
for data and client valuation because it consistently allocates a specified
utility among the players \citep{shapley1953value,ghorbani2019data}.

Classical Data Shapley repeatedly trains a model from scratch using only each
subset of clients and compares the resulting final performance. Applying this
definition at every FL round would require repeated client participation and
full retraining for each subset, which makes it impractical for online
valuation. Prior federated Shapley methods instead treat the updates received
in an actual round as the units of valuation, compute a contribution for each
round, and accumulate the resulting values over training. Even then, exact
Shapley computation requires enumerating client subsets, reconstructing a
model for each coalition, and evaluating it on a validation set; the cost
therefore grows exponentially with the number of participants. Sampling,
truncation, interpolation, and separate surrogate scores can reduce this cost,
but may introduce sampling variability or target a different utility. This
makes estimation error difficult to distinguish from a change in the game
being evaluated.

This paper asks the following question: using only the individual updates
observed by the server and a server-held validation set, can we attribute the
validation-loss improvement produced by an actual FedAvg round to its
participating clients in the Shapley sense, without evaluating a separate
model for every coalition? Answering this question first requires a game whose
grand coalition matches the aggregation actually performed by the server. The
game must then be computable online under partial participation. Finally, both
the exact reference being approximated and the source of approximation error
must be explicit.

We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator for this setting. Flirds treats each
client's weighted update in an observed round as a player and defines the
round utility as the reduction in validation loss obtained by applying only a
subset of those updates. Crucially, the weight of each client is held fixed at
the value used by the server rather than renormalized within every coalition.
The model displacement of the grand coalition therefore exactly matches the
actual FedAvg update. Exhaustive evaluation of this fixed-weight round game
yields the exact in-run Shapley value, but still requires exponentially many
validation evaluations per round. Flirds removes this enumeration by using
the computational idea of IRDS: it computes in closed form the Shapley value
of the second-order Taylor surrogate of the validation loss.

This construction connects the method directly to an operational FL setting.
The principal additional server computation is one Hessian-vector product
(HVP) on the validation set per round, followed by one inner product per
participant. Flirds requires neither additional communication nor additional
client-side computation, and its values can be accumulated online under
partial participation. Moreover, because Flirds and the exhaustively
enumerated reference target the same fixed-weight game, their difference can
be isolated as Taylor approximation error rather than conflated with a
different game definition or Shapley sampling error. We evaluate this
relationship by comparing both the rankings and numerical values against the
exact in-run Shapley reference, and we separately evaluate training
improvements under a shared intervention policy together with computational
cost. Our approach thus follows a measure-first principle: downstream success
is not treated as a substitute for estimator fidelity; the estimate is first
scored against the exact value of the same game.

Our contributions are as follows.
\begin{enumerate}
    \item \textbf{Efficient client contribution estimation.} Flirds computes
    in closed form the Shapley value of a second-order Taylor surrogate of the
    per-round validation loss. It requires only one server-side HVP per round
    and one inner product per participant, allowing contributions to be
    accumulated online under partial participation without coalition-wise
    model evaluation or Shapley sampling.
    \item \textbf{Direct verification against an exact reference.} We
    exhaustively evaluate the realized round utility to compute the exact
    in-run Shapley value and measure how faithfully Flirds approximates it at
    both the value and ranking levels. This protocol separates estimation
    accuracy from the effectiveness of downstream interventions and evaluates
    both in CNN and federated PEFT/LLM settings.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\textbf{Shapley-based contribution valuation in federated learning.}
FedSV \citep{wang2020principled} established a line of work that decomposes an
observed FL run into round-level games and reconstructs coalition models from
the updates received by the server. Exact round-level Shapley computation
still requires many coalition-utility evaluations, so FedSV uses permutation
sampling and group testing and analyzes their sample complexity. GTG-Shapley
\citep{liu2022gtg} uses guided Monte Carlo sampling and truncation both within
and across rounds under the same reconstruction framework. ComFedSV
\citep{fan2022improving} completes the utility matrix left incomplete by
partial participation using low-rank matrix completion. ShapleyFL, FedIF, and
the ShapFed family use Shapley-derived values or gradient similarity for
robust aggregation and client selection
\citep{sun2023shapleyfl,tang2025lightweight,tastan2024redefining}. Ripple
Shapley \citep{zeng2026ripple} estimates sample-level contribution in a single
federated training run by separating the direct effect in the current round
from effects propagated to later rounds, accumulating the latter through a
low-dimensional Jacobian approximation.

\textbf{Data attribution in centralized training.}
In non-federated settings, DataInf, EK-FAC, TRAK, and LoGra estimate
sample-level influence or attribution from individual training-example
gradients or curvature information
\citep{kwon2024datainf,grosse2023studying,park2023trak,choe2026your}.
LESS uses gradient similarity for targeted data selection
\citep{xia2024less}, while MATES and DsDm select subsets of large-scale
training data using a learned influence model or datamodel
\citep{yu2024mates,engstrom2024dsdm}. IRDS fixes one realized training
trajectory and accumulates the Shapley attribution of a per-step Taylor
utility \citep{wang2025data}. These centralized methods can directly access
individual samples and their derivative information, unlike an FL server.
Flirds adopts the additive-displacement calculation of IRDS but defines a
separate client-level game that incorporates fixed aggregation weights,
partial participation, and a server-held validation set.

\textbf{Quality evaluation, selection, and markets for federated LLMs.}
FedDQC assesses the quality of a client's local data through
instruction--response alignment and schedules training accordingly
\citep{du2025feddqc}. FedHDS selects coresets for federated instruction tuning
by reducing redundancy in representation space \citep{qin2025federated}.
iPFL jointly designs collaboration and payment rules in a personalized-model
market. These studies demonstrate quality control,
selection, or incentive mechanisms at the scale of federated large language
and foundation models, but they do not value each update in a realized
training run as Flirds does.

\section{Problem Formulation and Background on In-Run Attribution}
\label{sec:background}

\subsection{The Observed Federated Learning Run}
\label{sec:fedavg}

In FedAvg \citep{mcmahan2016federated}, a participating set
$P_r \subseteq [N]$ is selected in round $r$ from clients
$k \in [N] := \{1,\dots,N\}$, where client $k$ holds a local dataset of size
$n_k$. Each participating client trains locally from the current model $w^r$
and sends the resulting model difference $\Delta w_k^r$ to the server. For
$r=0,\dots,R{-}1$, the server aggregates these updates as
\begin{equation}
\label{eq:fedavg}
w^{r+1}
= w^r + \sum_{k \in P_r} p_k^r\,\Delta w_k^r,
\qquad
p_k^r = \frac{n_k}{\sum_{j \in P_r} n_j}.
\end{equation}
Here, $p_k^r$ is the weight used by the server for the realized participant
set $P_r$.

The server observes the client update $\Delta w_k^r$, not the underlying raw
data, and the realized model displacement in the round is a weighted sum of
these updates. We therefore use the submitted client updates as the units of
valuation and estimate each round's contributions from the realized update
vectors and the server's validation loss.

\subsection{Defining Contribution}
\label{sec:datashapley}

Given a player set and a coalition utility, the Shapley value averages each
player's marginal contribution over all participation orders. The value of
player $k$ is
\begin{equation}
\label{eq:shapley}
\phi_k(U)
= \sum_{S \subseteq [N]\setminus\{k\}}
\frac{|S|!\,(N{-}|S|{-}1)!}{N!}
\bigl(U(S\cup\{k\})-U(S)\bigr).
\end{equation}
Within the specified game, this value satisfies efficiency, symmetry, the
null-player property, and linearity \citep{shapley1953value}. The Shapley
formula itself, however, does not determine which utility is appropriate.
Contribution valuation must therefore begin by specifying the
counterfactual question that the game is intended to answer.

Classical Data Shapley uses as utility the final performance of a model
retrained from scratch using only the data in a coalition
\citep{ghorbani2019data}. It asks, ``What model would have been obtained had
only these clients participated in training?'' Round-level attribution for an
observed FL run asks a different question: ``Holding the current model and the
updates actually received fixed, how much did a subset of these updates
contribute to improving this round's model?'' The former is a counterfactual
over complete retraining, whereas the latter attributes change along a
realized trajectory. They are answers to different cooperative games. We take
the latter as our direct target and examine its relationship to the former
separately through experiments.

\subsection{The Computational Idea of In-Run Data Shapley}
\label{sec:irds}

In-Run Data Shapley (IRDS) \citep{wang2025data} fixes an actual training run
rather than repeatedly performing hypothetical retraining, and treats each
gradient step as a small cooperative game. Suppose that step $t$ updates the
model as
$w^{t+1}=w^t-\eta_t\sum_{z\in B_t}\nabla\ell_z(w^t)$.
For a subset $S\subseteq B_t$ of the batch, IRDS defines the utility
\begin{equation}
\label{eq:irds-utility}
u_t(S)
= \lval(w^t)
- \lval\left(
w^t-\eta_t\textstyle\sum_{z\in S}\nabla\ell_z(w^t)
\right).
\end{equation}
This utility is the decrease in validation loss obtained by applying only the
gradients of the samples in $S$. Summing the per-step Shapley values over the
realized run yields an in-run attribution for each sample along that
trajectory.

The computational key is that the model displacements of the players combine
additively. A Taylor expansion of the validation loss at the current model
contains a first-order term that measures the alignment between each player's
displacement and the validation gradient, and a second-order term that
captures curvature-mediated interactions with the other displacements in the
same step. Let
$g_t:=\nabla\lval(w^t)$ and $H_t:=\nabla^2\lval(w^t)$ denote the validation
gradient and Hessian. The Shapley value of the second-order surrogate can be
written as
\begin{multline}
\label{eq:irds-closed}
\phi_z(u_t)
\approx
\eta_t\left\langle g_t,\nabla\ell_z(w^t)\right\rangle\\
-\frac{\eta_t^2}{2}
\left\langle
\nabla\ell_z(w^t),
H_t\textstyle\sum_{z'\in B_t}\nabla\ell_{z'}(w^t)
\right\rangle.
\end{multline}
The calculation requires neither the full Hessian nor its inverse. A single
Hessian-vector product along the aggregate step direction supplies the
second-order term for every player.

The weighted sum of client updates in FedAvg provides the same additive
structure at client level. Simply replacing sample gradients with client
updates, however, does not fully specify the FL attribution problem. One must
also decide whether aggregation weights remain fixed or are renormalized
within each coalition, how to accumulate values when the participant set
changes across rounds, and which exact reference the estimate should be
compared against. The next section first defines a game that preserves the
actual FedAvg displacement and then explains how Flirds reduces the cost of
computing that game's Shapley values.

\section{Flirds: The Federated In-Run Game and Its Closed-Form Estimation}
\label{sec:flirds}

\subsection{The Federated Game and the Two Ground Truths}
\label{sec:game}

The classical ground truth of data valuation, the \emph{exact retrain
Shapley}, retrains from scratch for $R$ rounds with only the client subset $S$
participating and takes the validation-loss decrease of the resulting final
model $w_S^R$ (with $w_\emptyset^R = w^0$),
\begin{equation}\label{eq:retrain}
U^{\mathrm{re}}(S) = \lval(w^0) - \lval\big(w_S^R\big),
\end{equation}
whose Shapley value $\phi_k^{\mathrm{re}} = \phi_k(U^{\mathrm{re}})$ is
computed without approximation by retraining all $2^N$ subsets (a
method-neutral ground truth; the question it asks is the counterfactual ``had
only $S$ participated''). The round structure of FL, meanwhile, corresponds
exactly to the step structure of IRDS: in the step game of
Eq.~\eqref{eq:irds-utility}, substituting the round's weighted per-client
update $p_k^r \Delta w_k^r$ for the sample gradient term
$-\eta_t \nabla \ell_z$ transplants the game to the client level, and the
ingredients are nothing but what the server receives anyway under the standard
protocol. We freeze the realized trajectory
$\{w^r, \{\Delta w_k^r\}_{k \in P_r}\}_{r=0}^{R-1}$ (the \emph{frozen
trajectory}; every method below consumes this same training log) and define
the per-round coalition utility, for $S \subseteq P_r$, as
\begin{equation}\label{eq:round-utility}
u_r(S) = \lval(w^r)
- \lval\Big(w^r + \textstyle\sum_{k \in S} p_k^r\, \Delta w_k^r\Big).
\end{equation}
The weights are the \emph{fixed weights} $p_k^r$ that the run itself used; we
do not renormalize within $S$. Renormalizing within $S$, as some baselines do
(GTG-Shapley, FedSV), is not an implementation detail but a \emph{different
cooperative game}: a zero-update free-rider comes to receive a nonzero value;
there are counterexamples in which rankings flip under unequal data sizes,
partial participation, and second-order curvature (Appendix~A); and the
sum-form structure that folds a round into a single HVP breaks, so the
closed-form computation no longer holds. The \emph{exact in-run Shapley}
$\phi^{\mathrm{in}}$ is the sum of each round game's Shapley value computed
without approximation by exhaustively enumerating all $2^{|P_r|}$ subsets per
round: $\phi_k^{\mathrm{in}} = \sum_{r:\, k \in P_r} \phi_k(u_r)$. The
efficiency of IRDS carries over, combined with telescoping:
$\sum_k \phi_k^{\mathrm{in}} = \sum_{r=0}^{R-1} u_r(P_r)
= \lval(w^0) - \lval(w^R)$.

\textbf{Terminology.} Throughout, ground truth (oracle) refers to exactly two
objects: the \emph{exact retrain Shapley} above (exhaustive per-subset
retraining) and the \emph{exact in-run Shapley} just defined (exhaustive
per-round enumeration). We always use the full names and never an unqualified
``exact.'' For both, larger is more beneficial (positive when the validation
loss is reduced).

\subsection{The Closed-Form Estimator}
\label{sec:estimator}

The exact in-run Shapley involves no approximation, but it demands
$2^{|P_r|}$ validation evaluations per round. Flirds starts from the fact that
the Shapley value of $\hat u_r$, the approximate game obtained by
Taylor-expanding the round utility to second order around $w^r$, comes out in
closed form (Proposition~\ref{prop:closed}). Writing
$g_r := \nabla \lval(w^r)$, $H_r := \nabla^2 \lval(w^r)$ (the true Hessian,
not a Gauss--Newton approximation), $\delta_k^r := \Delta w_k^r$, the
aggregate displacement of a coalition
$\Delta_S^r := \sum_{k \in S} p_k^r\, \delta_k^r$, and
$\Delta W_r := \Delta_{P_r}$:
\begin{equation}\label{eq:closed}
\begin{split}
\hat\phi_k^{(r)}
&= -\,p_k^r\, \big\langle g_r,\, \delta_k^r \big\rangle
- \tfrac{1}{2}\, p_k^r\, \big\langle \delta_k^r,\; H_r\, \Delta W_r
\big\rangle, \\
\hat\phi_k &= \sum_{r\,:\,k\in P_r} \hat\phi_k^{(r)}.
\end{split}
\end{equation}
The first term measures how well $k$'s update aligns with the descent
direction of the validation loss; the second, the \emph{client-interaction
term}, measures how $k$'s update composes, through curvature, with the other
participants' aggregate update. (The sign of the first term differs from
Eq.~\eqref{eq:irds-closed} because there the displacement
$-\eta_t \nabla \ell_z$ carries an explicit minus sign, whereas here
$\delta_k^r$ is itself the displacement.) All a round requires is \emph{one}
Hessian-vector product (HVP) $H_r \Delta W_r$, computed with forward-mode
automatic differentiation, plus one inner product per participant. No Hessian
is ever materialized or inverted, and the cost is independent of the number of
subsets $2^{|P_r|}$. The variant with the second-order term removed is called
\emph{Flirds (first-order)} and serves as an ablation of the interaction term.

\subsection{Theory: The Estimator and the Exact In-Run Shapley Compute the
Same Game}
\label{sec:theory}

The point of this section is one sentence: Flirds computes not an arbitrary
score but the Shapley value of precisely the game defined by
Eq.~\eqref{eq:round-utility}, and its sole difference from the exact in-run
Shapley is the Taylor truncation. Formal statements, proofs, assumptions,
counterexamples, and numerical verification are in Appendix~A.

\begin{proposition}[Per-round decomposition]\label{prop:decomp}
On the frozen trajectory, the Shapley value of the total game $\sum_r u_r$
(each $u_r$ extended to a game on $[N]$ by $u_r(S) := u_r(S \cap P_r)$ before
summing) decomposes exactly into the sum of the Shapley values of the
per-round $|P_r|$-player games. (That non-participating rounds contribute
zero is a theorem, not a definition.)
\end{proposition}

\begin{proposition}[Closed form; free-rider zero; efficiency]
\label{prop:closed}
For the second-order Taylor approximation game $\hat u_r$ of the round
utility, the exact Shapley value equals Eq.~\eqref{eq:closed} exactly:
$\hat\phi_k^{(r)} = \phi_k(\hat u_r)$ (proof in Appendix~A). Two corollaries:
a zero-update free-rider with $\delta_k^r = 0$ in every participating round
receives \emph{exactly} $\hat\phi_k = 0$ algebraically, and the values sum to
the total utility of the approximate game (efficiency).
\end{proposition}

\begin{proposition}[Taylor residual]\label{prop:residual}
The price of the approximation is truncation error. The per-round utility
error is bounded by $\frac{M_3^r}{6}\|\Delta_S^r\|^3$ at second order and by
$\frac{M_2^r}{2}\|\Delta_S^r\|^2$ at first order, and accumulates linearly in
the number of rounds (the per-round local curvature constants
$M_2^r, M_3^r$ are defined formally in Appendix~A). These constants are not
estimable quantities, so what the bound delivers is the \emph{order} of the
residual (its scaling law).
\end{proposition}

\begin{remark}[Scope]
The exact in-run Shapley is a function of the realized trajectory, and
therefore inherits IRDS's unresolved axiomatization of trajectory-specific
values (its relation to the exact retrain Shapley is an empirical question
rather than a theoretical one, and Section~5.3 reports it as such). The game
is defined at \emph{client} granularity, the unit the FL protocol exposes to
the server; the formal per-sample-to-per-client bridge holds under mean losses
and a single local step (Appendix~A) and does not transfer as-is to token-mean
LLM losses. In the LLM track, $w$, $\delta_k^r$, $g_r$, and $H_r$ are all
quantities in the LoRA-factor coordinates that the server actually exchanges
and averages (the CNN track trains full parameters, so no distinction arises;
the formal treatment of coordinate dependence is in Appendix~A.10).
\end{remark}
