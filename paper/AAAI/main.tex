\begin{abstract}
Client contribution evaluation in federated learning (FL) quantifies how much
each participant's update contributed to improving the jointly trained model.
Because an FL server does not hold the clients' raw data, it cannot by itself
carry out the classical data Shapley valuation that rests on subset
retraining, and contributions must instead be evaluated from the updates
received in actual rounds. Even with updates as the unit of evaluation,
however, an exact computation requires enumerating participant subsets in
every round and reconstructing and evaluating a model for each of them, so
its cost grows exponentially with the number of participants.
We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator. Flirds defines a cooperative game whose
players are the client updates actually received by the server, with that
round's server aggregation weights held fixed across all coalitions, and
extends the Taylor calculation of In-Run Data Shapley (IRDS) to the level of
client updates, computing the Shapley value of a second-order surrogate game
in closed form. This computes what would require exponentially many coalition
evaluations with one server-side Hessian-vector product per round and one
inner product per participant, with no additional communication and no
client-side computation.
\end{abstract}

\section{Introduction}
\label{sec:intro}

In federated learning (FL), clients jointly train a single model without
sharing their raw data \citep{mcmahan2016federated}. In each round, the
server collects the updates sent by the participating clients and improves
the model, but the aggregate alone does not directly reveal how much each
client contributed to that improvement. Such contribution estimates can serve
as grounds not only for participant compensation but also for data-quality
management, free-rider detection, client selection, and debugging of the
training process. The Shapley value from cooperative game theory provides a
principle for consistently allocating a specified utility among the
participants, and has therefore been widely used for evaluating data and
client contributions \citep{shapley1953value,ghorbani2019data}.

Classical Data Shapley trains the model from scratch on each subset of the
data and compares the resulting final performance. An FL server, however,
does not hold the clients' raw data, so it cannot perform subset retraining
on its own; retraining amounts to re-running the entire federation and
repeatedly requesting the clients' cooperation. This definition is therefore
not an option available to the server for reasons of information structure,
before cost even enters, and still less can it serve as an online evaluation
tool in settings where clients participate intermittently. Prior federated
Shapley methods have instead taken the updates the server receives in an
actual round as the units of evaluation, computed per-round contributions,
and accumulated them over training. Even then, obtaining exact Shapley values
requires enumerating participant subsets in every round, reconstructing a
model for each coalition, and evaluating it on a validation set, so the cost
grows exponentially with the number of participants.

The problem this paper addresses is therefore the following: using only the
individual updates observed by the server and a validation set, can we
attribute the validation-loss improvement produced by an actual FedAvg round
to the participating clients in the Shapley sense, while avoiding
per-coalition model evaluation? This requires first defining a game whose
grand coalition coincides with the aggregation the server actually performed,
and that game must be computable online under partial participation. It must
also be possible to state separately which game's Shapley value the computed
quantity approximates and where the approximation error arises.

We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator for this problem. Flirds views each
client's weighted update in an actual round as a player and defines the round
utility as the decrease in validation loss obtained when only a subset of
those updates is applied. The weight of each client is not renormalized
within each coalition but held fixed at the value used in the actual server
aggregation. The model displacement of the grand coalition therefore
coincides exactly with the actual FedAvg update. Exhaustively evaluating this
round game yields the per-round Shapley values, but still requires
exponentially many validation evaluations per round. Flirds removes this
enumeration by using the computational idea of In-Run Data Shapley (IRDS): it
computes in closed form the Shapley value of the second-order Taylor
surrogate of the validation loss.

This construction connects the method directly to the federated learning
setting. The principal additional server computation Flirds requires per
round is one Hessian-vector product (HVP) on the validation set, and the
per-participant computation is a single inner product. It needs no additional
communication or client-side computation, and the values of partially
participating rounds can be accumulated online. Defining a game that matches
the actual FL run, computing it efficiently, comparing it against the Shapley
values obtained by exhaustively enumerating the same game, and measuring
actual training effects to validate both accuracy and practical
effectiveness: this is the structure of the paper.

Our contributions are as follows.
\begin{enumerate}
    \item \textbf{A Shapley game for the observed federated round.} We
    formalize a validation-loss game whose players are the client updates
    observed in a synchronous FedAvg round, with the actual aggregation
    weights held fixed, making the estimand explicit
    (Sections~\ref{sec:datashapley} and~\ref{sec:game}).
    \item \textbf{A closed-form second-order estimator with interpretable
    error.} We carry the second-order Taylor derivation of IRDS over to the
    client and round level and obtain in closed form the surrogate Shapley
    value of the observed round game, avoiding the exponentially many
    coalition evaluations. The difference from the Shapley value obtained by
    exhaustively enumerating the original round game reduces to the per-round
    Taylor residual (Sections~\ref{sec:estimator} and~\ref{sec:theory}).
    \item \textbf{Validation of accuracy and practical effectiveness.} We
    evaluate the accuracy of the estimates against the per-round Shapley
    values obtained by exhaustive enumeration. We then validate actual
    training improvement under a shared intervention policy and report the
    computational cost of each method (Section~\ref{sec:experiments}).
\end{enumerate}

\section{Related Work}
\label{sec:related}

\textbf{Shapley-based contribution evaluation in federated learning.}
The common bottleneck of this line of work is the exponential number of
coalition evaluations that the Shapley value demands. FedSV
\citep{wang2020principled} reduces the number of coalitions to be evaluated
through permutation sampling and group testing, as does GTG-Shapley
\citep{liu2022gtg}, which reconstructs submodels from stored updates, through
guided Monte Carlo sampling and truncation; ComFedSV
\citep{fan2022improving} and SPACE \citep{chen2023space} instead replace or
complement the computation of the coalition utilities themselves, with
low-rank completion and a prototype-based utility respectively. ShapleyFL and
the FedIF and ShapFed families use Shapley-derived values or gradient
similarity for robust aggregation and client selection
\citep{sun2023shapleyfl,tang2025lightweight,tastan2024redefining}. Ripple
Shapley \citep{zeng2026ripple} decomposes sample-level contribution in a
single federated training run into the direct effect in the current round and
the effects propagated to later rounds, accumulating the latter through a
low-dimensional Jacobian approximation; because its unit of evaluation is the
sample and it targets cross-round influence propagation, its target of
evaluation differs from ours, the client-level contribution in the observed
round game.

\textbf{Data contribution evaluation in centralized training.}
In centralized training, the training party has direct access to individual
samples and their derivative information, and sample-level attribution has
developed on that premise: DataInf, EK-FAC, TRAK, and LoGra estimate
influence and attribution from gradient or curvature information
\citep{kwon2024datainf,grosse2023studying,park2023trak,choe2026your}, and
LESS, MATES, and DsDm use such signals for targeted data selection
\citep{xia2024less,yu2024mates,engstrom2024dsdm}. In-Run Data Shapley (IRDS)
\citep{wang2025data} is the method in this lineage that our paper takes as
its starting point: instead of hypothetical retraining, it fixes a single
actual training run and accumulates the per-step Shapley values of the
validation loss, computed in closed form via Taylor expansion. Flirds brings
to the federated setting the computational structure of IRDS, in which the
Shapley value of the second-order surrogate game admits a closed form once
the per-player displacements combine additively.

\textbf{Quality evaluation, selection, and markets for federated LLMs.}
FedDQC \citep{du2025feddqc} assesses the quality of a client's internal data
through instruction--response alignment and schedules training accordingly,
and FedHDS \citep{qin2025federated} selects coresets for federated
instruction tuning using redundancy in representation space. iPFL jointly
designs collaboration and payment rules in a personalized-model market. These
studies show that quality control, selection, or incentive mechanisms are
feasible at the scale of federated large language and foundation models.

\section{Problem Setup and Background}
\label{sec:background}

\subsection{Federated Learning Setup and Notation}
\label{sec:fedavg}

In FedAvg \citep{mcmahan2016federated}, clients $k \in [N] := \{1,\dots,N\}$
hold local datasets of size $n_k$, and in round $r$ a participating set
$P_r \subseteq [N]$ performs local training from the current model $w^r$.
Client $k$ sends the resulting model difference $\Delta w_k^r$ to the server,
which aggregates, for $r=0,\dots,R{-}1$,
\begin{equation}
\label{eq:fedavg}
w^{r+1}
= w^r + \sum_{k \in P_r} p_k^r\,\Delta w_k^r,
\qquad
p_k^r = \frac{n_k}{\sum_{j \in P_r} n_j}.
\end{equation}
Here, $p_k^r$ is the weight the server used for the actual participating set
$P_r$.

What the server observes for each client is not raw data but the update
$\Delta w_k^r$, and the model displacement of the actual round is a weighted
sum of these updates. This paper therefore takes the updates submitted by the
clients as the units of evaluation and evaluates each round's contributions
from the observed update vectors and the server's validation loss.

\subsection{Contribution via the Shapley Value}
\label{sec:datashapley}

Given a player set and a coalition utility, the Shapley value averages each
player's marginal contribution over all participation orders. The value of
player $k$ is
\begin{equation}
\label{eq:shapley}
\phi_k(U)
= \sum_{S \subseteq [N]\setminus\{k\}}
\frac{|S|!\,(N{-}|S|{-}1)!}{N!}
\bigl(U(S\cup\{k\})-U(S)\bigr).
\end{equation}
Within the specified game, this value satisfies efficiency, symmetry, the
null-player property, and linearity \citep{shapley1953value}, but the Shapley
formula itself does not determine which utility is the right one. Client
contribution evaluation must therefore decide, before any computation, which
counterfactual question it is to answer.

Classical Data Shapley uses as utility the final performance of a model
retrained from scratch using only the data in a coalition
\citep{ghorbani2019data}. It asks, ``What model would have been obtained had
only these clients participated in training?'' Per-round contribution in an
actual FL run asks a different question: ``Holding the current model and the
updates actually received fixed, how much did a subset of these updates
contribute to improving this round's model?'' The former is a counterfactual
over complete retraining, whereas the latter is attribution along a realized
trajectory; the two values are answers to different games. We take the latter
as our direct target and analyze its relationship to the former separately
and empirically.

\subsection{In-Run Data Shapley}
\label{sec:irds}

In-Run Data Shapley (IRDS) \citep{wang2025data} fixes an actual training run
rather than repeatedly performing hypothetical retraining, and views each
gradient step as a small cooperative game. When step $t$ updates the model as
$w^{t+1}=w^t-\eta_t\sum_{z\in B_t}\nabla\ell_z(w^t)$, where $\ell_z$ is the
loss of sample $z$ in the minibatch $B_t$ and $\eta_t$ the learning rate, and
writing $\lval$ for the loss on the validation set,
the utility of a batch subset $S\subseteq B_t$ is set to
\begin{equation}
\label{eq:irds-utility}
u_t(S)
= \lval(w^t)
- \lval\left(
w^t-\eta_t\textstyle\sum_{z\in S}\nabla\ell_z(w^t)
\right).
\end{equation}
That is, the decrease in validation loss obtained by applying only the
gradients of some of the samples is taken as the value of that coalition.
Summing each step's Shapley values over the actual training run yields a
per-sample in-run attribution for that trajectory.

The computational key of IRDS is that the per-player model displacements
combine additively. Taylor-expanding the validation loss at the current
model, the first-order term captures the alignment between each player's
displacement and the validation gradient, and the second-order term captures
the curvature effect that arises when a displacement combines with the other
displacements of the same step. Writing
$g_t:=\nabla\lval(w^t)$ and $H_t:=\nabla^2\lval(w^t)$ for the gradient and
Hessian of the validation loss, the Shapley value of the second-order
surrogate is
\begin{multline}
\label{eq:irds-closed}
\phi_z(u_t)
\approx
\eta_t\left\langle g_t,\nabla\ell_z(w^t)\right\rangle\\
-\frac{\eta_t^2}{2}
\left\langle
\nabla\ell_z(w^t),
H_t\textstyle\sum_{z'\in B_t}\nabla\ell_{z'}(w^t)
\right\rangle.
\end{multline}
The important point is that the second-order term of every player can be
computed not from the full Hessian or its inverse, but from a single
Hessian-vector product along the full step direction.

The weighted sum of client updates in FedAvg provides the structure needed to
apply this computational idea at the client level. Substituting client updates
for sample gradients, however, does not by itself fix the game. In the IRDS
step game the expansion interval is a single step, every sample of a batch
receives the same coefficient, and the player set is given by the batch, so
three questions that stayed buried there remain open in FL.
(i)~\emph{The unit of the game}: the server observes not a step but only the
accumulated result of several local steps, so the expansion interval becomes
much larger than a step and the standing of an approximation that leaned on
the premise of small steps changes.
(ii)~\emph{The coefficients of a subset}: $p_k^r$ differs across clients, so
one may instead renormalize over the remaining participants, and which of the
two is chosen divides the game itself.
(iii)~\emph{Accumulation across participants}: the player set differs from
round to round, so what it means to add per-round values has to be defined
first. The next section settles these three and shows what each decision
guarantees.

\subsection{The Federated Round Game}
\label{sec:game}

The round structure of FL corresponds formally to the step structure of IRDS:
in the step game of Eq.~\eqref{eq:irds-utility}, substituting the round's
weighted per-client update $p_k^r\,\Delta w_k^r$ for the sample-gradient term
$-\eta_t \nabla\ell_z$ defines the same additive structure at the level of
client updates. We fix the realized trajectory
$\{w^r, \{\Delta w_k^r\}_{k \in P_r}\}_{r=0}^{R-1}$ and define the per-round
coalition utility, for $S \subseteq P_r$, as
\begin{equation}\label{eq:round-utility}
u_r(S) = \lval(w^r)
- \lval\Big(w^r + \textstyle\sum_{k \in S} p_k^r\, \Delta w_k^r\Big).
\end{equation}
The players are the clients' weighted updates, each submitted after multiple
local steps, and the coefficients $p_k^r$ are the values the actual
aggregation used, without renormalizing within a coalition. The displacement
of the coalition containing all participants therefore coincides exactly with
the aggregation the server actually performed. Because the unit is a round
rather than a step, this game differs from the IRDS step game
(Appendix~A.5), and the game with renormalized coefficients is likewise a
different game (Appendix~A.6).

We call the value obtained by computing this game's Shapley value through
exhaustive enumeration of the $2^{|P_r|}$ subsets in each round and
accumulating over rounds the \emph{in-run Shapley} $\phi^{\mathrm{in}}$:
$\phi_k^{\mathrm{in}} = \sum_{r:\, k \in P_r} \phi_k(u_r)$. Although the
player set changes from round to round, if a client that did not participate
in a round is taken to leave the utility unchanged when added to a coalition
($u_r(S) = u_r(S \cap P_r)$), every round game becomes a game on the full
client set, and the sum above coincides exactly with the Shapley value of the
whole-run game $U^{\mathrm{in}} := \sum_r u_r$ (the same argument as IRDS's
summation over steps; Appendix~A.2). Combining per-round efficiency
$\sum_k \phi_k(u_r) = u_r(P_r)$ with the fact that the grand coalition's
displacement is the actual aggregation gives
$u_r(P_r) = \lval(w^r) - \lval(w^{r+1})$, so the intermediate terms telescope
when rounds are summed and the values of all clients add up to the
validation-loss improvement of the entire run:
$\sum_k \phi_k^{\mathrm{in}} = \sum_{r=0}^{R-1} u_r(P_r)
= \lval(w^0) - \lval(w^R)$.

For comparison we also carry the classical definition of data valuation
transported to the client level: the Shapley value of the validation-loss
decrease $U^{\mathrm{re}}(S) = \lval(w^0) - \lval(w_S^R)$ of the final model
$w_S^R$ (with $w_\emptyset^R = w^0$) obtained by retraining $R$ rounds from
scratch with only the client subset $S$ participating, computed by exhaustive
retraining of all $2^N$ subsets. Following IRDS's terminology, we call this
the \emph{retraining-based Shapley} $\phi^{\mathrm{re}}$, with
$\phi_k^{\mathrm{re}} = \phi_k(U^{\mathrm{re}})$. The relation between the two
values is characterized empirically in Section~\ref{sec:fidelity}.

\subsection{The Closed-Form Estimator}
\label{sec:estimator}

Exhaustive enumeration of the in-run Shapley involves no approximation but
requires $2^{|P_r|}$ validation evaluations per round. Flirds starts from the
fact that the Shapley value of $\hat u_r$, the approximate game obtained by
Taylor-expanding the round utility to second order around $w^r$, comes out in
closed form (Theorem~4 of IRDS; Appendix~A.3). Writing
$g_r := \nabla \lval(w^r)$, $H_r := \nabla^2 \lval(w^r)$,
$\delta_k^r := \Delta w_k^r$, the aggregate displacement of a coalition
$\Delta_S^r := \sum_{k \in S} p_k^r\, \delta_k^r$, and
$\Delta W_r := \Delta_{P_r}^r$:
\begin{equation}\label{eq:closed}
\begin{split}
\hat\phi_k^{(r)}
&= -\,p_k^r\, \big\langle g_r,\, \delta_k^r \big\rangle
- \tfrac{1}{2}\, p_k^r\, \big\langle \delta_k^r,\; H_r\, \Delta W_r
\big\rangle, \\
\hat\phi_k &= \sum_{r\,:\,k\in P_r} \hat\phi_k^{(r)}.
\end{split}
\end{equation}
The first term measures how well $k$'s update alone aligns with the descent
direction of the validation loss. The second, the \emph{second-order
curvature term}, distributes the share by which $k$'s update couples through
curvature with the round's entire aggregate displacement. The variant with the
second-order term removed is called \emph{Flirds-1st} and is used as an
ablation of the curvature term. The sign of the first term differs
from Eq.~\eqref{eq:irds-closed} because here $\delta_k^r$ is itself the
displacement.

This closed form holds because the coalition displacement $\Delta_S^r$ remains
a sum of coalition-independent vectors $p_k^r\,\delta_k^r$, a structure that
arises precisely because Section~\ref{sec:game} fixed the coefficients
independently of the subset. Under renormalized coefficients the displacement
is not expressible as such a sum for any assignment of vectors, so the
derivation does not even start (Appendix~A.5).

\textbf{Cost.} The only heavy per-round computations are the validation
gradient $g_r$ and the Hessian-vector product (HVP) $H_r \Delta W_r$, and both
are obtained together from a single Jacobian-vector product (JVP) call that
layers forward-mode differentiation over the gradient function
(forward-over-reverse; primal output $= g_r$, tangent output
$= H_r \Delta W_r$). The per-participant computation is one
inner product with $v_r := g_r + \tfrac12 H_r \Delta W_r$
(Algorithm~\ref{alg:flirds}; the side costs are $O(|P_r|\,d)$ inner products
in the parameter dimension $d$ and storing the updates within a round). No
Hessian is ever materialized or inverted, and the cost is independent of the
number of subsets $2^{|P_r|}$.

\begin{algorithm}[t]
\caption{Flirds (server side; one round $r$). Lines 3--6 correspond
one-to-one to the implementation's \texttt{jvp(grad(vloss), \ldots)} call and
the folding of $v_r$.}
\label{alg:flirds}
\begin{algorithmic}[1]
\REQUIRE model $w^r$, participants $P_r$, updates $\{\delta_k^r\}$, data
sizes $\{n_k\}$, validation set $D_{\mathrm{val}}$
\STATE $p_k^r \gets n_k / \sum_{j \in P_r} n_j$
\COMMENT{actual aggregation weights (Eq.~\eqref{eq:fedavg})}
\STATE $\Delta W_r \gets \sum_{k \in P_r} p_k^r\, \delta_k^r$
\COMMENT{aggregate displacement the server computes anyway}
\STATE $(g_r, h_r) \gets \mathrm{jvp}(\nabla \lval,\, w^r;\, \Delta W_r)$
\COMMENT{one call: primal $= g_r$, tangent $= H_r \Delta W_r$}
\STATE $v_r \gets g_r + \tfrac12 h_r$
\FOR{$k \in P_r$}
\STATE $\hat\phi_k \gets \hat\phi_k - p_k^r\, \langle \delta_k^r, v_r \rangle$
\COMMENT{equivalent to Eq.~\eqref{eq:closed}; one inner product}
\ENDFOR
\STATE $w^{r+1} \gets w^r + \Delta W_r$
\COMMENT{standard FedAvg aggregation (Eq.~\eqref{eq:fedavg})}
\ENSURE accumulated contributions $\hat\phi$ (no extra client computation or
communication; identical when recomputed post hoc from frozen logs)
\end{algorithmic}
\end{algorithm}

\subsection{The Shapley Axioms and the Approximation Error}
\label{sec:theory}

Flirds does not compute the nonlinear game of Eq.~\eqref{eq:round-utility}
itself exactly. What it computes exactly is the \emph{Shapley value of the
second-order Taylor surrogate} that uses the same fixed trajectory, the same
aggregation weights, and the same expansion point, so its difference from the
in-run Shapley is only the per-round Taylor truncation. The Shapley axioms
hold exactly on this approximate game, so no axiom violation arises
(Remark~3 of IRDS), and their holding takes concrete form in three properties
that are used directly in the operation of FL. (i)~A client is a null player
in the game of a round it did not participate in and therefore receives zero,
so the server can simply assign values to that round's participants each
round and add them up. (ii)~A zero-update free-rider with $\delta_k^r = 0$ in
every participating round is also a null player, and in
Eq.~\eqref{eq:closed} both terms are inner products with the zero vector, so
it receives $\hat\phi_k = 0$ \emph{algebraically exactly}. (iii)~The values
sum to the total improvement of the surrogate game (efficiency).

How large, then, is the error? Eq.~\eqref{eq:closed} takes the Taylor
expansion of the validation loss up to the second-order term, so the error is
the tail from the truncated third-order term onward (from the second-order
term onward for the first-order surrogate). In the IRDS step game the
expansion displacement is $-\eta_t\sum_{z\in B_t}\nabla\ell_z$, so this tail
falls with the cube of the learning rate, $O(\eta_t^3)$, and the fact that the
learning rate is small justifies the truncation. Here the expansion
displacement is the round displacement $\Delta_S^r$ of a coalition,
accumulated over several local steps, so the same logic applies with only the
unit changed: the residual is $O(\|\Delta_S^r\|^3)$, and
$O(\|\Delta_S^r\|^2)$ for the first-order surrogate, and since a Shapley value
is a weighted average of coalition marginals, this order propagates unchanged
to the player-level values and to the accumulation over rounds. A round
displacement, however, is not guaranteed to be as small as a single step, so
the truncation is not automatically justified. The bound with its conditions
and constants stated, together with its limitations, is in Appendix~A.4, and
the actual size of the error is measured by comparison against the value
obtained by exhaustively enumerating the same game
(Section~\ref{sec:fidelity}).

\subsection{Experimental Setup}
\label{sec:setup}

\textbf{Settings.} The main settings are one LLM setting and one CNN setting,
and both tracks share the same configuration: partial-participation FL with
corrupted clients mixed in. The LLM track evaluates Llama-family models
\citep{grattafiori2024llama,touvron2023llama} on GSM8K
\citep{cobbe2021training}, Alpaca-GPT4 \citep{peng2023instruction}, and a
five-domain dataset we constructed, and the CNN track evaluates FedSVCNN and
LeNet5 \citep{lecun1998gradient} on CIFAR-10 \citep{krizhevsky2009learning},
MNIST, and Fashion-MNIST \citep{xiao2017fashion}. The corruption axis has five
entries: \emph{clean} (the uncorrupted control anchor), \emph{answer-swap}
(data that is well formed but whose question--response correspondence is
broken by a permutation; LLM), \emph{zero-update free-rider} (submitting a
zero update without local training), \emph{gradient noise} (Gaussian noise
injected into the update after normal training; CNN), and \emph{label-flip}
(labels replaced at random; CNN).

\textbf{Compared methods.} The comparison uses eight contribution methods.
Flirds is the second-order closed-form estimator of Eq.~\eqref{eq:closed}
proposed in this paper, Flirds-1st is the variant of the same expression that
keeps only the first-order term, and \emph{singleton utility} is an additive
approximation that computes the round game's singleton utility $u_r(\{k\})$
itself directly by forward evaluation and sums it over rounds, using
singleton values in place of Shapley values. Alongside these we place five
methods representing the prior lineage of Section~\ref{sec:related}.
GTG-Shapley and FedSV define the utility of a coalition reconstructed from
stored updates with the weights renormalized within that coalition, ComFedSV
fills a partially populated utility matrix by low-rank completion, and
ShapleyFL and FedIF use as the client score a Shapley-derived value and a
gradient-similarity-based influence respectively.

\textbf{Metrics.} We begin with the sign convention. Since $u_r$ in
Eq.~\eqref{eq:round-utility} is the decrease in validation loss, lowering the
loss counts as contributing more. For fidelity, Spearman's $\rho$ (ranking)
and Pearson's $r$ (values) are reported in the body, and Kendall's $\tau$
together with three distances (cosine, Euclidean, max) in Appendix~C.
Interventions are read directly off performance: test accuracy for the CNN
track and exact match (EM) of the final generated answer for the LLM track,
seen together with vanilla (no intervention) and with oracle-exclusion, the
reference arm that excludes exactly the corrupted clients.

\subsection{Fidelity}
\label{sec:fidelity}

This section answers the first question: how faithfully do Flirds and
Flirds-1st reproduce the Shapley value of the game they target, the in-run
Shapley obtained by exhaustively enumerating the round game of
Eq.~\eqref{eq:round-utility}? The scoring procedure is common to all methods.
In each cell (setting $\times$ threat $\times$ seed) we freeze a single
training trajectory and score every method and the in-run Shapley on the same
log, so that the differences between methods are the methods' own and not
trajectory variance. Rank reproduction is read with Spearman's $\rho$ and
value reproduction with Pearson's $r$. What the scoring standard itself
means, that is, when the in-run Shapley agrees with the retraining-based
Shapley, is characterized separately in Appendix~C.0.

\subsection{Contribution-Based Intervention}
\label{sec:intervention}

On the training-improvement axis of the effectiveness check, we ask whether
performance improves when the measured contributions are used in an actual
training decision. The policy is fixed to a single rule, sign-gating, which
excludes the clients whose accumulated contribution satisfies
$\hat\phi_k \le 0$. The algebraically exact zero of property~(ii) in
Section~\ref{sec:theory}, together with the fact that the accumulated sign of
a clean client is positive, makes the threshold $\tau = 0$ natural, so there
is no hyperparameter to tune. Because the policy is held fixed and only the
method that supplies the scores (the score source) is swapped, this section
is also a direct test of whether the fidelity of
Section~\ref{sec:fidelity} carries over into a downstream ordering. The body
reports the selection-retrain view, in which the set of clients to keep is
decided by the final accumulated signs of an observer run that is
bit-identical to the trajectory without intervention, and training is then
repeated from the initial weights; the online view, which gates immediately
in every round, is in Appendix~G.0. The controls are vanilla (the observer),
oracle-exclusion, which excludes exactly the corrupted clients, and
selection-random, which keeps a random set of the same size.

\subsection{Cost}
\label{sec:cost}

Where the previous two sections addressed accuracy and practical
effectiveness, this section measures their price. What is measured is the
computation the server additionally spends on contribution evaluation, and
the local training time of the clients is kept separate and used only as a
baseline for the comparison. There are two axes. One is a
hardware-independent operation-count model that pins down, for each method,
the number of dominant operations per round (HVP, gradient, forward); the
other is wall-clock time measured on the same trajectory and the same stack.
We read the two together because measurements alone vary with
reimplementation, precision, and hardware, while operation counts alone do
not show the actual burden. What this section sets out to establish is not
that some method is always cheaper, but that the ratios between the methods
are predicted as a function of the number of participants in a round.

\subsection{Ablation: The Second-Order Curvature Term}
\label{sec:ablation}

Finally we isolate what the second-order curvature term of
Eq.~\eqref{eq:closed} does. The control is Flirds-1st, the same expression
with that one term removed, so the difference between the two values is
attributable to the curvature term alone. The previous two sections and
Appendix~F have already reported the two variants side by side in the same
settings, so rather than adding a new experiment we read across the three
axes of fidelity, intervention, and detection (Appendix~F) to see when the
first-order approximation breaks down. The claim this section establishes is
therefore not that the second-order term is needed in every regime, but the
conditional one that it guards against the failure of the first-order
approximation in regimes where curvature effects are large and in regimes
where participation is sparse.

\section{Limitations}
\label{sec:limitations}

The most fundamental premise is that the server's validation set is the judge
of value. Since the utility of the game is the validation loss, the
composition of that set determines the meaning of every value. If the premise
that the validation set is fair to all clients breaks down, through the
under-representation of a particular group or task, the clients who are
useful to that group are structurally undervalued, and contributions that lie
outside the distribution the validation set covers are not visible in the
game at all, so they cannot be evaluated.

Next, the numbers Flirds produces are not the intrinsic value of data but a
conditional attribution of the validation-loss decrease of one realized
trajectory. The lottery of which client was drawn in which round is not
corrected for, the Shapley axioms are properties inside the frozen round
game, and the axiomatization of trajectory-specific utilities is an open
problem. The sum of the closed form is efficiency within the second-order
surrogate game, so a gap from the realized improvement, the Taylor residual,
remains in every round.

Finally, the closed form and the realized-trajectory semantics depend on
synchronous FedAvg, in which the individual updates are observed and
aggregated additively, on a stateless server without momentum, and on
stateless clients. Server momentum and Adam break these semantics, and in a
setting such as Secure Aggregation \citep{bonawitz2017practical}, where only
the sum is exposed, the per-client inner products cannot be computed.

\section{Conclusion}
\label{sec:conclusion}

Flirds turns the validation-loss game of an observed FedAvg round, with the
actual aggregation weights held fixed, into a second-order Taylor surrogate
and computes its Shapley value in closed form with one HVP per round and one
inner product per client. It is a construction that removes the re-evaluation
of coalitions while keeping the game that is computed, the in-run Shapley,
and the approximation residual separately auditable.
