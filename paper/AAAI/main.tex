\begin{abstract}
Client contribution evaluation in federated learning (FL) quantifies how much
each participant's update contributed to improving the jointly trained model.
Because an FL server does not hold the clients' raw data, it cannot by itself
perform the subset retraining on which classical data valuation is based, and
contributions must instead be evaluated from the updates received in actual
rounds. The Shapley value provides a consistent attribution principle within
a specified cooperative game, but computing it exactly requires exponentially
many coalition evaluations in the number of participating clients, and
existing approximations reduce this cost at the price of obscuring what is
being approximated and how the error should be interpreted.
We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator. Flirds defines a cooperative game whose
players are the client updates actually received by the server, with the
round's server aggregation weights held fixed across all coalitions, and
extends the Taylor calculation of In-Run Data Shapley (IRDS) to client
updates, computing the Shapley value of a second-order surrogate game in
closed form. This replaces the exponential coalition evaluations with one
server-side Hessian-vector product per round and one inner product per
participant, with no additional communication or client-side computation.
Because the estimates are compared against the per-round Shapley values
obtained by exhaustively enumerating the same game, their difference can be
interpreted as the Taylor residual rather than a difference in game
definition or sampling error. Experiments validate the accuracy of the
estimates through ranking and value comparisons against this reference, and
their practical effectiveness through actual training improvement under a
shared intervention policy together with measured computational cost.
\end{abstract}

\section{Introduction}
\label{sec:intro}

In federated learning (FL), clients jointly train a single model without
sharing their raw data \citep{mcmahan2016federated}. In each round, the
server collects the updates sent by the participating clients and improves
the model, but the aggregate alone does not directly reveal how much each
client contributed to that improvement. Such contribution estimates can serve
as grounds not only for participant compensation but also for data-quality
management, free-rider detection, client selection, and debugging of the
training process. The Shapley value from cooperative game theory provides a
principle for consistently allocating a specified utility among the
participants, and has therefore been widely used for evaluating data and
client contributions \citep{shapley1953value,ghorbani2019data}.

Classical Data Shapley retrains the model from scratch with each subset of
clients and compares the resulting final performance. An FL server, however,
does not hold the clients' raw data, so it cannot perform subset retraining
on its own; retraining amounts to re-running the entire federation and
repeatedly requesting the clients' cooperation. This definition is therefore
not an option available to the server for reasons of information structure,
before cost even enters, and still less can it serve as an online evaluation
tool in settings where clients participate intermittently. Prior federated
Shapley methods have instead taken the updates the server receives in an
actual round as the units of evaluation, computed per-round contributions,
and accumulated them over training. Even then, obtaining exact Shapley values
requires enumerating participant subsets in every round, reconstructing a
model for each coalition, and evaluating it on a validation set, so the cost
grows exponentially with the number of participants. Sampling, truncation,
interpolation, or separate alternative scores can reduce this cost, but they
may add sampling variability or compute a utility different from the original
target, which makes estimation error hard to distinguish from a change in the
game definition.

The problem this paper addresses is therefore the following: using only the
individual updates observed by the server and a validation set, can we
attribute the validation-loss improvement produced by an actual FedAvg round
to the participating clients in the Shapley sense, while avoiding
per-coalition model evaluation? This requires first defining a game whose
grand coalition coincides with the aggregation the server actually performed,
and that game must be computable online under partial participation. It must
also be possible to state separately which game's Shapley value the computed
quantity approximates and where the approximation error arises.

We propose \textbf{Flirds} (Federated Learning In-Run Data Shapley), a
client-level contribution estimator for this problem. Flirds views each
client's weighted update in an actual round as a player and defines the round
utility as the decrease in validation loss obtained when only a subset of
those updates is applied. The weight of each client is not renormalized
within each coalition but held fixed at the value used in the actual server
aggregation. The model displacement of the grand coalition therefore
coincides exactly with the actual FedAvg update. Exhaustively evaluating this
round game yields the per-round Shapley values, but still requires
exponentially many validation evaluations per round. Flirds removes this
enumeration by using the computational idea of In-Run Data Shapley (IRDS): it
computes in closed form the Shapley value of the second-order Taylor
surrogate of the validation loss.

This construction connects the method directly to the federated learning
setting. The principal additional server computation Flirds requires per
round is one Hessian-vector product (HVP) on the validation set, and the
per-participant computation is a single inner product. It needs no additional
communication or client-side computation, and the values of partially
participating rounds can be accumulated online. Furthermore, because Flirds
is a Taylor approximation of the per-round Shapley values, the difference
between the two can be interpreted as Taylor approximation error, separated
from differences in game definition or Shapley sampling error. We verify this
relationship by comparing rankings and values against the per-round Shapley
values computed by exhaustive enumeration, and we evaluate training
improvement under a shared intervention policy together with computational
cost. Defining a game that matches the actual FL run, computing it
efficiently, comparing it against the reference obtained by exhaustively
enumerating the same game, and measuring actual training effects to validate
both accuracy and practical effectiveness: this is the structure of the
paper.

Our contributions are as follows.
\begin{enumerate}
    \item \textbf{A Shapley game for the observed federated round.} We
    formalize a validation-loss game whose players are the client updates
    observed in a synchronous FedAvg round, with the actual aggregation
    weights held fixed. Because the grand coalition exactly reproduces the
    actual aggregation, the estimand is explicit, and in-run attribution is
    separated from retraining-based data valuation
    (Sections~\ref{sec:datashapley} and~\ref{sec:game}).
    \item \textbf{A closed-form second-order estimator with interpretable
    error.} We carry the second-order Taylor derivation of IRDS over to the
    client and round level and obtain in closed form the surrogate Shapley
    value of the observed round game. This replaces the exponentially many
    coalition evaluations with one aggregate-direction server HVP per round
    and one inner product per participant. The Shapley axioms hold exactly on
    the surrogate game, and the difference from the Shapley value obtained by
    exhaustively enumerating the original round game reduces to the per-round
    Taylor residual (Sections~\ref{sec:estimator} and~\ref{sec:theory}).
    \item \textbf{Validation of accuracy and practical effectiveness.} We
    evaluate the ranking and value accuracy of the estimates against the
    per-round Shapley values obtained by exhaustive enumeration. We then
    validate the practical effectiveness of the measured contributions
    through actual training improvement under a shared intervention policy,
    and report measured computational cost for all methods
    (Section~\ref{sec:experiments}).
\end{enumerate}

\section{Related Work}
\label{sec:related}

\textbf{Shapley-based contribution evaluation in federated learning.}
The common bottleneck of this line of work is the exponential number of
coalition evaluations that the Shapley value demands, and
subsequent research has developed in two directions: reducing the number of
coalitions to evaluate, or replacing and complementing the coalition-utility
computation. FedSV \citep{wang2020principled} introduced permutation sampling
and group testing, and GTG-Shapley \citep{liu2022gtg} combined guided Monte
Carlo sampling with truncation within and across rounds on top of submodel
reconstruction from stored updates. ComFedSV \citep{fan2022improving}
completes the utility matrix left partially empty by partial participation
via low-rank matrix completion. SPACE \citep{chen2023space}, in contrast,
introduces single-round knowledge amalgamation and a prototype-based utility,
reducing the cost of multi-round reconstruction and of evaluation that scales
with validation-set size. ShapleyFL and the FedIF and ShapFed families use
Shapley-derived values or gradient similarity for robust aggregation and
client selection
\citep{sun2023shapleyfl,tang2025lightweight,tastan2024redefining}. Ripple
Shapley \citep{zeng2026ripple} decomposes sample-level contribution in a
single federated training run into the direct effect in the current round and
the effects propagated to later rounds, accumulating the latter through a
low-dimensional Jacobian approximation; because its unit of evaluation is the
sample and it targets cross-round influence propagation, its target of
evaluation differs from ours, the client-level contribution in the observed
round game.

\textbf{Data contribution evaluation in centralized training.}
In centralized training, the training party has direct access to individual
samples and their derivative information, and sample-level attribution has
developed on that premise: DataInf, EK-FAC, TRAK, and LoGra estimate
influence and attribution from gradient or curvature information
\citep{kwon2024datainf,grosse2023studying,park2023trak,choe2026your}, and
LESS, MATES, and DsDm use such signals for targeted data selection
\citep{xia2024less,yu2024mates,engstrom2024dsdm}. In-Run Data Shapley (IRDS)
\citep{wang2025data} is the method in this lineage that our paper takes as
its starting point: instead of hypothetical retraining, it fixes a single
actual training run and accumulates the per-step Shapley values of the
validation loss, computed in closed form via Taylor expansion. What an FL server observes, however, is not samples but the
updates submitted by clients, so these methods do not transfer as they are.
What Flirds takes from IRDS is the computational structure in which, once the
per-player model displacements combine additively, the Shapley value of the
second-order surrogate game admits a closed form.

\textbf{Quality evaluation, selection, and markets for federated LLMs.}
FedDQC \citep{du2025feddqc} assesses the quality of a client's internal data
through instruction--response alignment and schedules training accordingly,
and FedHDS \citep{qin2025federated} selects coresets for federated
instruction tuning using redundancy in representation space. iPFL jointly
designs collaboration and payment rules in a personalized-model market. These
studies show that quality control, selection, or incentive mechanisms are
feasible at the scale of federated large language and foundation models, but
they do not compute how much each client's update improved the jointly
trained model in a realized training run.

\section{Problem Setup and Background}
\label{sec:background}

\subsection{Federated Learning Setup and Notation}
\label{sec:fedavg}

In FedAvg \citep{mcmahan2016federated}, clients $k \in [N] := \{1,\dots,N\}$
hold local datasets of size $n_k$, and in round $r$ a participating set
$P_r \subseteq [N]$ performs local training from the current model $w^r$.
Client $k$ sends the resulting model difference $\Delta w_k^r$ to the server,
which aggregates, for $r=0,\dots,R{-}1$,
\begin{equation}
\label{eq:fedavg}
w^{r+1}
= w^r + \sum_{k \in P_r} p_k^r\,\Delta w_k^r,
\qquad
p_k^r = \frac{n_k}{\sum_{j \in P_r} n_j}.
\end{equation}
Here, $p_k^r$ is the weight the server used for the actual participating set
$P_r$.

What the server observes for each client is not raw data but the update
$\Delta w_k^r$, and the model displacement of the actual round is a weighted
sum of these updates. This paper therefore takes the updates submitted by the
clients as the units of evaluation and evaluates each round's contributions
from the observed update vectors and the server's validation loss.

\subsection{Contribution via the Shapley Value}
\label{sec:datashapley}

Given a player set and a coalition utility, the Shapley value averages each
player's marginal contribution over all participation orders. The value of
player $k$ is
\begin{equation}
\label{eq:shapley}
\phi_k(U)
= \sum_{S \subseteq [N]\setminus\{k\}}
\frac{|S|!\,(N{-}|S|{-}1)!}{N!}
\bigl(U(S\cup\{k\})-U(S)\bigr).
\end{equation}
Within the specified game, this value satisfies efficiency, symmetry, the
null-player property, and linearity \citep{shapley1953value}, but the Shapley
formula itself does not determine which utility is the right one. Client
contribution evaluation must therefore decide, before any computation, which
counterfactual question it is to answer.

Classical Data Shapley uses as utility the final performance of a model
retrained from scratch using only the data in a coalition
\citep{ghorbani2019data}. It asks, ``What model would have been obtained had
only these clients participated in training?'' Per-round contribution in an
actual FL run asks a different question: ``Holding the current model and the
updates actually received fixed, how much did a subset of these updates
contribute to improving this round's model?'' The former is a counterfactual
over complete retraining, whereas the latter is attribution along a realized
trajectory; the two values are answers to different games. We take the latter
as our direct target and analyze its relationship to the former separately
and empirically.

\subsection{In-Run Data Shapley}
\label{sec:irds}

In-Run Data Shapley (IRDS) \citep{wang2025data} fixes an actual training run
rather than repeatedly performing hypothetical retraining, and views each
gradient step as a small cooperative game. When step $t$ updates the model as
$w^{t+1}=w^t-\eta_t\sum_{z\in B_t}\nabla\ell_z(w^t)$, where $\ell_z$ is the
loss of sample $z$ in the minibatch $B_t$ and $\eta_t$ the learning rate, and
writing $\lval$ for the loss on the validation set,
the utility of a batch subset $S\subseteq B_t$ is set to
\begin{equation}
\label{eq:irds-utility}
u_t(S)
= \lval(w^t)
- \lval\left(
w^t-\eta_t\textstyle\sum_{z\in S}\nabla\ell_z(w^t)
\right).
\end{equation}
That is, the decrease in validation loss obtained by applying only the
gradients of some of the samples is taken as the value of that coalition.
Summing each step's Shapley values over the actual training run yields a
per-sample in-run attribution for that trajectory.

The computational key of IRDS is that the per-player model displacements
combine additively. Taylor-expanding the validation loss at the current
model, the first-order term captures the alignment between each player's
displacement and the validation gradient, and the second-order term captures
the curvature effect that arises when a displacement combines with the other
displacements of the same step. Writing
$g_t:=\nabla\lval(w^t)$ and $H_t:=\nabla^2\lval(w^t)$ for the gradient and
Hessian of the validation loss, the Shapley value of the second-order
surrogate is
\begin{multline}
\label{eq:irds-closed}
\phi_z(u_t)
\approx
\eta_t\left\langle g_t,\nabla\ell_z(w^t)\right\rangle\\
-\frac{\eta_t^2}{2}
\left\langle
\nabla\ell_z(w^t),
H_t\textstyle\sum_{z'\in B_t}\nabla\ell_{z'}(w^t)
\right\rangle.
\end{multline}
The important point is that the second-order term of every player can be
computed not from the full Hessian or its inverse, but from a single
Hessian-vector product along the full step direction.

The weighted sum of client updates in FedAvg provides the structure needed to
apply this computational idea at the client level. Substituting client updates
for sample gradients, however, does not by itself fix the game. In the IRDS
step game the expansion interval is a single step, every sample of a batch
receives the same coefficient, and the player set is given by the batch, so
three questions that stayed buried there remain open in FL.
(i)~\emph{The unit of the game}: the server observes not a step but only the
accumulated result of several local steps, so the expansion interval becomes
much larger than a step and the standing of an approximation that leaned on
the premise of small steps changes.
(ii)~\emph{The coefficients of a subset}: $p_k^r$ differs across clients, so
one may instead renormalize over the remaining participants, and which of the
two is chosen divides the game itself.
(iii)~\emph{Accumulation across participants}: the player set differs from
round to round, so what it means to add per-round values has to be defined
first. The next section settles these three and shows what each decision
guarantees.

\subsection{The Federated Round Game}
\label{sec:game}

The round structure of FL corresponds formally to the step structure of IRDS:
in the step game of Eq.~\eqref{eq:irds-utility}, substituting the round's
weighted per-client update $p_k^r\,\Delta w_k^r$ for the sample-gradient term
$-\eta_t \nabla\ell_z$ defines the same additive structure at the level of
client updates. We fix the realized trajectory
$\{w^r, \{\Delta w_k^r\}_{k \in P_r}\}_{r=0}^{R-1}$ and define the per-round
coalition utility, for $S \subseteq P_r$, as
\begin{equation}\label{eq:round-utility}
u_r(S) = \lval(w^r)
- \lval\Big(w^r + \textstyle\sum_{k \in S} p_k^r\, \Delta w_k^r\Big).
\end{equation}
The players are the clients' weighted updates, each submitted after multiple
local steps, and the coefficients $p_k^r$ are the values the actual
aggregation used, without renormalizing within a coalition. The displacement
of the coalition containing all participants therefore coincides exactly with
the aggregation the server actually performed. Because the unit is a round
rather than a step, this game differs from the IRDS step game
(Appendix~A.5), and the game with renormalized coefficients is likewise a
different game (Appendix~A.6).

We call the value obtained by computing this game's Shapley value through
exhaustive enumeration of the $2^{|P_r|}$ subsets in each round and
accumulating over rounds the \emph{in-run Shapley} $\phi^{\mathrm{in}}$:
$\phi_k^{\mathrm{in}} = \sum_{r:\, k \in P_r} \phi_k(u_r)$. Although the
player set changes from round to round, if a client that did not participate
in a round is taken to leave the utility unchanged when added to a coalition
($u_r(S) = u_r(S \cap P_r)$), every round game becomes a game on the full
client set, and the sum above coincides exactly with the Shapley value of the
whole-run game $U^{\mathrm{in}} := \sum_r u_r$ (the same argument as IRDS's
summation over steps; Appendix~A.2). Combining per-round efficiency
$\sum_k \phi_k(u_r) = u_r(P_r)$ with the fact that the grand coalition's
displacement is the actual aggregation gives
$u_r(P_r) = \lval(w^r) - \lval(w^{r+1})$, so the intermediate terms telescope
when rounds are summed and the values of all clients add up to the
validation-loss improvement of the entire run:
$\sum_k \phi_k^{\mathrm{in}} = \sum_{r=0}^{R-1} u_r(P_r)
= \lval(w^0) - \lval(w^R)$.

For comparison we also carry the classical definition of data valuation
transported to the client level: the Shapley value of the validation-loss
decrease $U^{\mathrm{re}}(S) = \lval(w^0) - \lval(w_S^R)$ of the final model
$w_S^R$ (with $w_\emptyset^R = w^0$) obtained by retraining $R$ rounds from
scratch with only the client subset $S$ participating, computed by exhaustive
retraining of all $2^N$ subsets. Following IRDS's terminology, we call this
the \emph{retraining-based Shapley} $\phi^{\mathrm{re}}$, with
$\phi_k^{\mathrm{re}} = \phi_k(U^{\mathrm{re}})$. The relation between the two
values is characterized empirically in Section~\ref{sec:fidelity}.

\subsection{The Closed-Form Estimator}
\label{sec:estimator}

Exhaustive enumeration of the in-run Shapley involves no approximation but
requires $2^{|P_r|}$ validation evaluations per round. Flirds starts from the
fact that the Shapley value of $\hat u_r$, the approximate game obtained by
Taylor-expanding the round utility to second order around $w^r$, comes out in
closed form (Theorem~4 of IRDS; Appendix~A.3). Writing
$g_r := \nabla \lval(w^r)$, $H_r := \nabla^2 \lval(w^r)$,
$\delta_k^r := \Delta w_k^r$, the aggregate displacement of a coalition
$\Delta_S^r := \sum_{k \in S} p_k^r\, \delta_k^r$, and
$\Delta W_r := \Delta_{P_r}^r$:
\begin{equation}\label{eq:closed}
\begin{split}
\hat\phi_k^{(r)}
&= -\,p_k^r\, \big\langle g_r,\, \delta_k^r \big\rangle
- \tfrac{1}{2}\, p_k^r\, \big\langle \delta_k^r,\; H_r\, \Delta W_r
\big\rangle, \\
\hat\phi_k &= \sum_{r\,:\,k\in P_r} \hat\phi_k^{(r)}.
\end{split}
\end{equation}
The first term measures how well $k$'s update alone aligns with the descent
direction of the validation loss. The second, the \emph{second-order
curvature term}, distributes the share by which $k$'s update couples through
curvature with the round's entire aggregate displacement. The variant with the
second-order term removed is called \emph{Flirds-1st} and is used as an
ablation of the curvature term. The sign of the first term differs
from Eq.~\eqref{eq:irds-closed} because here $\delta_k^r$ is itself the
displacement.

This closed form holds because the coalition displacement $\Delta_S^r$ remains
a sum of coalition-independent vectors $p_k^r\,\delta_k^r$, a structure that
arises precisely because Section~\ref{sec:game} fixed the coefficients
independently of the subset. Under renormalized coefficients the displacement
is not expressible as such a sum for any assignment of vectors, so the
derivation does not even start (Appendix~A.5).

\textbf{Cost.} The only heavy per-round computations are the validation
gradient $g_r$ and the Hessian-vector product (HVP) $H_r \Delta W_r$, and both
are obtained together from a single Jacobian-vector product (JVP) call that
layers forward-mode differentiation over the gradient function
(forward-over-reverse; primal output $= g_r$, tangent output
$= H_r \Delta W_r$). The per-participant computation is one
inner product with $v_r := g_r + \tfrac12 H_r \Delta W_r$
(Algorithm~\ref{alg:flirds}; the side costs are $O(|P_r|\,d)$ inner products
in the parameter dimension $d$ and storing the updates within a round). No
Hessian is ever materialized or inverted, and the cost is independent of the
number of subsets $2^{|P_r|}$.

\begin{algorithm}[t]
\caption{Flirds (server side; one round $r$). Lines 3--6 correspond
one-to-one to the implementation's \texttt{jvp(grad(vloss), \ldots)} call and
the folding of $v_r$.}
\label{alg:flirds}
\begin{algorithmic}[1]
\REQUIRE model $w^r$, participants $P_r$, updates $\{\delta_k^r\}$, data
sizes $\{n_k\}$, validation set $D_{\mathrm{val}}$
\STATE $p_k^r \gets n_k / \sum_{j \in P_r} n_j$
\COMMENT{actual aggregation weights (Eq.~\eqref{eq:fedavg})}
\STATE $\Delta W_r \gets \sum_{k \in P_r} p_k^r\, \delta_k^r$
\COMMENT{aggregate displacement the server computes anyway}
\STATE $(g_r, h_r) \gets \mathrm{jvp}(\nabla \lval,\, w^r;\, \Delta W_r)$
\COMMENT{one call: primal $= g_r$, tangent $= H_r \Delta W_r$}
\STATE $v_r \gets g_r + \tfrac12 h_r$
\FOR{$k \in P_r$}
\STATE $\hat\phi_k \gets \hat\phi_k - p_k^r\, \langle \delta_k^r, v_r \rangle$
\COMMENT{equivalent to Eq.~\eqref{eq:closed}; one inner product}
\ENDFOR
\STATE $w^{r+1} \gets w^r + \Delta W_r$
\COMMENT{standard FedAvg aggregation (Eq.~\eqref{eq:fedavg})}
\ENSURE accumulated contributions $\hat\phi$ (no extra client computation or
communication; identical when recomputed post hoc from frozen logs)
\end{algorithmic}
\end{algorithm}

\subsection{The Shapley Axioms and the Approximation Error}
\label{sec:theory}

Flirds does not compute the nonlinear game of Eq.~\eqref{eq:round-utility}
itself exactly. What it computes exactly is the \emph{Shapley value of the
second-order Taylor surrogate} that uses the same fixed trajectory, the same
aggregation weights, and the same expansion point, so its difference from the
in-run Shapley is only the per-round Taylor truncation. The Shapley axioms
hold exactly on this approximate game, so no axiom violation arises
(Remark~3 of IRDS), and their holding takes concrete form in three properties
that are used directly in the operation of FL. (i)~A client is a null player
in the game of a round it did not participate in and therefore receives zero,
so the server can simply assign values to that round's participants each
round and add them up. (ii)~A zero-update free-rider with $\delta_k^r = 0$ in
every participating round is also a null player, and in
Eq.~\eqref{eq:closed} both terms are inner products with the zero vector, so
it receives $\hat\phi_k = 0$ \emph{algebraically exactly}. (iii)~The values
sum to the total improvement of the surrogate game (efficiency).

How large, then, is the error? Eq.~\eqref{eq:closed} takes the Taylor
expansion of the validation loss up to the second-order term, so the error is
the tail from the truncated third-order term onward (from the second-order
term onward for the first-order surrogate). In the IRDS step game the
expansion displacement is $-\eta_t\sum_{z\in B_t}\nabla\ell_z$, so this tail
falls with the cube of the learning rate, $O(\eta_t^3)$, and the fact that the
learning rate is small justifies the truncation. Here the expansion
displacement is the round displacement $\Delta_S^r$ of a coalition,
accumulated over several local steps, so the same logic applies with only the
unit changed: the residual is $O(\|\Delta_S^r\|^3)$, and
$O(\|\Delta_S^r\|^2)$ for the first-order surrogate, and since a Shapley value
is a weighted average of coalition marginals, this order propagates unchanged
to the player-level values and to the accumulation over rounds. A round
displacement, however, is not guaranteed to be as small as a single step, so
the truncation is not automatically justified. The bound with its conditions
and constants stated, together with its limitations, is in Appendix~A.4, and
the actual size of the error is measured by comparison against the value
obtained by exhaustively enumerating the same game
(Section~\ref{sec:fidelity}).

\subsection{Experimental Setup}
\label{sec:setup}

\textbf{Settings.} The main settings are one LLM setting and one CNN setting,
and both tracks share the same configuration: partial-participation FL with
corrupted clients mixed in. The LLM track consists of a main setting that
trains Llama-3.2-1B(-Instruct) \citep{grattafiori2024llama} with LoRA
\citep{hu2022lora} on GSM8K \citep{cobbe2021training}, together with two
auxiliary settings, a five-domain non-IID setting and an IID-clean Alpaca
setting \citep{taori2023stanford}. The CNN track consists of a main setting
that trains CIFAR-10 \citep{krizhevsky2009learning} with FedSVCNN and MNIST
with LeNet5 \citep{lecun1998gradient} under two partitions, IID and
Dirichlet($\alpha{=}1$), together with an auxiliary grid setting that trains
the same
datasets and models with full participation. The corruption axis has five
entries: \emph{clean} (the uncorrupted control anchor), \emph{answer-swap}
(data that is well formed but whose question--response correspondence is
broken by a permutation; LLM), \emph{zero-update free-rider} (submitting a
zero update without local training), \emph{gradient noise} (Gaussian noise
injected into the update after normal training; CNN), and \emph{label-flip}
(labels replaced at random; CNN). The number of clients, the participation,
and the number of rounds of each setting are stated in the caption of the
corresponding results table, and the full list of models, hyperparameters,
data partitioning, and threat implementations is in Appendix~B.

\textbf{Compared methods.} We divide the eight contribution methods by the
game they target. Three of them target Eq.~\eqref{eq:round-utility}: Flirds
(the second-order closed form), Flirds-1st (the first-order term only), and
\emph{singleton utility}, an additive approximation that evaluates the round
game's singleton utility $u_r(\{k\})$ directly by forward evaluation and sums
it over rounds, using singleton values in place of Shapley values. The
remaining five, GTG-Shapley, FedSV, ComFedSV, ShapleyFL, and FedIF, target
different values exactly as in the lineage of Section~\ref{sec:related}: a
renormalized game, an interpolated utility matrix, processed surrogate
scores, or influence.

\textbf{Metrics.} We begin with the sign convention. Since $u_r$ in
Eq.~\eqref{eq:round-utility} is the decrease in validation loss, lowering the
loss counts as contributing more. For fidelity, Spearman's $\rho$ (ranking)
and Pearson's $r$ (values) are reported in the body, and Kendall's $\tau$
together with three distances (cosine, Euclidean, max) in Appendix~C.
Interventions are read directly off performance: test accuracy for the CNN
track and exact match (EM) of the final generated answer for the LLM track,
seen together with vanilla (no intervention) and with oracle-exclusion, the
reference arm that excludes exactly the corrupted clients.

\subsection{Fidelity}
\label{sec:fidelity}

\textbf{Summary.} Flirds reproduces the in-run Shapley consistently in both
main settings, and the first-order approximation collapses under gradient
noise. The relation between the retraining-based Shapley and the in-run
Shapley is conditional: in the five-domain non-IID setting, where the signal
is genuine, the two values agree at $+1.000$ in 9 of 9 cells, whereas in the
clean IID cells the agreement falls to $-0.27$ (Appendix~C.3), and the amount
by which Flirds departs from the retraining-based Shapley is indistinguishable
from the amount by which the in-run Shapley itself departs from it (paired
difference over 43 cells, $-0.020\pm.055$). The cells of the LLM main setting
have not yet completed three seeds and are treated as preliminary.

This section answers two questions in turn. It first measures, in the CNN and
LLM main settings, whether the estimator matches the value it targets, and
then characterizes, in the small-$N$ settings where the latter is computable,
when the in-run Shapley that serves as that standard agrees with the
retraining-based Shapley. The scoring procedure is common to all methods. For
each cell (setting $\times$ threat $\times$ seed) we run one training
trajectory, freeze it, and score every method and the in-run Shapley on the
same logs (the protocol of Section~\ref{sec:game}), so that differences
between methods are the methods' own and not trajectory variance. Only the
retraining-based Shapley performs separate per-subset retraining, by
definition.

correlations in cells such as clean, where the variance of the target values
across clients is small, are not counted as evidence of superiority for any
method. The methods that target other games are not included in this table

is in Appendix~C.1.

the in-run Shapley enumerates $2^5$ subsets per round. In the completed

free-rider is an algebraic consequence of the estimator

achievement; the free-rider column of Table~\ref{tab:cnn-fidelity} is not
trivial because it ranks the benign clients as well, so we report it as it
stands, while the operational value of the algebraic zero is measured by the
intervention (Section~\ref{sec:intervention}) and by detection
(Appendix~F). The clean cells are a candidate signal-absent regime in which
the in-run Shapley ranking itself does not reproduce across seeds
(Appendix~D.2), so we neither read a low $\rho$ there as a failure of the
method nor conclude from it that there is nothing to measure; these cells
serve only as a control for false firing.

differences (method minus in-run Shapley, 43 cells), Flirds is

$+0.017\pm.096$, so neither is distinguishable from the in-run Shapley itself,
whereas Flirds-1st at $-0.200\pm.423$ and ShapleyFL at $-0.210\pm.509$ do
separate. The share by which Flirds fails to agree completely is therefore not
estimation error but the difference between the two games, and there is little
left for the estimator to reduce in this setting.

We report the ordering of methods as it stands. Averaged over the three
corrupted cells (cifar10, 18 cells), singleton utility at $+0.785$ is higher
than Flirds at $+0.756$ and is also close to the in-run Shapley itself
($+0.776$), so Flirds is not the sole leader on this axis. On the other hand,
the sign reversal of Flirds-1st under gradient noise ($-0.184/-0.204$) and
that of ShapleyFL under the zero-update free-rider ($-0.211/-0.562$) reproduce
here as well, and when the same cells are scored against the in-run Shapley,
Flirds leads the entire comparison set at $+0.975\pm.035$ (Appendix~C.2).
Which Shapley value one scores against changes the ordering. Taken together,
the conclusion about the retraining-based Shapley is limited to a conditional
characterization over three small-$N$ settings, and the answer at the scale of
the main settings is carried by the in-run Shapley axis
(Table~\ref{tab:cnn-fidelity} and Appendix~C.1).

\subsection{Contribution-Based Intervention}
\label{sec:intervention}

\textbf{Summary.} In the CNN main setting the strengths and failures of
sign-gating differ by threat, and Flirds separates from the low-cost
derivative-based comparison methods under gradient noise. The structure
reproduces under the IID partition and on MNIST, while the size of the gap
depends on task difficulty. In the LLM main setting sign-gating beats both
random controls, but the score sources do not separate from one another.

This is the training-improvement axis of the practical-effectiveness
validation of Section~\ref{sec:intro}. There is a single policy, sign-gating,
which excludes every client whose accumulated contribution satisfies
$\hat\phi_k \le 0$. The algebraically exact zero of a zero-update client and
the positive accumulation of clean clients (Section~\ref{sec:theory}) make the
threshold $\tau{=}0$ a natural cut, so there is no hyperparameter to tune.
There are two points at which it can be applied. Online gating gates
immediately at each round on the sign accumulated up to that point, whereas
selection-retrain fixes the kept set from the final accumulated signs of an
observer run and retrains from the initial model. An observer run is a run
that follows a trajectory bit-identical to vanilla, with all scoring methods
(score sources) attached at once so that only scores are collected; each arm
then trains a new trajectory from those scores, so the meaning of a trajectory
is not mixed with the fixed-trajectory scoring of
Section~\ref{sec:fidelity}. The controls are vanilla, oracle-exclusion (the
reference that excludes exactly the corrupted clients), random-exclusion (the
same number of clients removed at random), and selection-random (retraining
with a random kept set of the same size, which separates the value of the
ranking information from the effect of the set size). Because only the score
source is swapped under the same policy, this section is also a direct test of
whether the fidelity of Section~\ref{sec:fidelity} carries over into
downstream superiority.

\textbf{CNN main setting.} Table~\ref{tab:cnn-intervention} is a competition
in which eight score sources are swapped into the same policy, the same
setting, and the same seeds. The corrupted-mean column averages the three
threats within a seed first, and the last column is the paired difference to
vanilla in the corrupted mean of the same seed.

The four threats separate different things. Under the zero-update free-rider,
the semantics of zero decides whether the gate lives or dies. The methods with
an algebraic zero (Flirds, Flirds-1st, singleton utility, FedIF) reach $.61$
to $.62$, close to the oracle-exclusion reference ($.620$), whereas the four
renormalizing methods fall to $.39$ to $.40$ under online gating, below even
vanilla ($.588$). Renormalizing within a coalition keeps allotting a share to
the zero-update client, so the gate retains the corrupted clients and evicts
sound ones (the argument for the choice of game in
Section~\ref{sec:game}); under selection-retrain, where there is no online
compounding of the damage, this is mitigated to $.51$ to $.52$. Gradient noise
is the discriminating cell for the second-order term. Among the low-cost
derivative-based methods, only the second-order Flirds recovers, to $.5668$
online and $.6065$ under retraining, while Flirds-1st and FedIF, which use
first-order information only, remain at $.2479$ and $.2436$, the level of
vanilla ($.2436$). The singleton utility, which uses singleton forwards
directly, also captures the nonlinear effect at $.5981$ and $.4518$, so the
second-order term is not the only remedy (Section~\ref{sec:ablation}).
Label-flip is where the retraining point wins: every estimator rises from the
$.57$ range online to the $.62$ range under selection-retrain, close to
oracle-exclusion.

We also report false firing on clean data as it stands. Under online gating
the paired means are $-0.7$ points for Flirds and $-1.3$ points for singleton
utility, while Flirds-1st and FedIF barely fire at all. Among the methods
targeting Eq.~\eqref{eq:round-utility}, Flirds excludes the most clean clients
under retraining (24 to 36 of 100 under the Dirichlet partition), and widening
to all score sources, the renormalizing and GTG-Shapley families exclude more
still, 34 to 48 (per-seed counts in Appendix~G.4). The per-round count of
clean exclusions under online gating is not preserved by the current analysis
outputs, so a separate ledger is needed for a final conclusion on operational
risk. In sum, the strength of Flirds is not that it leads in every cell but
that it separates from the low-cost derivative-based comparison methods in the
gradient-noise cell, where second-order curvature is needed; individual cells
are also won by FedIF, by singleton utility, and by methods targeting other
games.

The controls show that the gain is not an effect of removing a given number of
clients. Against retraining with a random kept set of the same size, the
corrupted-mean difference of Flirds is $+.1866\pm.0315$ ($+.3921\pm.0205$ in
the gradient-noise cell), whereas the four renormalizing methods are negative
under the free-rider, $-.051$ to $-.063$ (full ledger in Appendix~G.2). The
same structure reproduces when the partition is changed to IID and when the
dataset is changed to MNIST (full ledgers and the differences in detail in
Appendices~G.1 and~G.5). What changes is the size of the gap. On MNIST the
task is easy, so the oracle-exclusion reference itself sits low ($.9780$) and
the gaps between methods at the retraining point narrow to about one standard
deviation; under the IID partition the retraining kept set for label-flip
becomes the same for all methods, so that cell no longer resolves them. Even
under full 100/100 participation, sign-gating exceeds vanilla in all three
corrupted cells, so the gain of the gate is not a product of the dilution
caused by partial participation (Appendix~E.1).

\textbf{LLM main setting.} We checked the same policy in the LLM main setting
(EM; full ledger in Appendix~G.0, corrupted cells over 3 seeds, clean column
preliminary). Under answer-swap, sign-gating gains $+1.5$ to $+2.2$ points
over vanilla regardless of the point of application and of the score source.
This falls short of oracle-exclusion ($+3.5$ points) but separates clearly
from the two controls (random exclusion of the same number,
$+.0006\pm.0014$; size-matched random retraining, $-.0054\pm.0164$). Under the
zero-update free-rider, the kept set under retraining is exactly the 30 benign
clients for all four score sources, so the retraining coincides with
oracle-exclusion and the EM values agree to the last decimal in every seed.
This is the cell in which the algebraic zero of
Section~\ref{sec:theory} translates directly into a policy decision. The
online gain in the same cell is indistinguishable from zero, because excluding
a zero-update client barely changes the aggregate, so the value of the
exclusion is realized only in retraining, which spends the training budget
again. Under clean data the kept set under retraining is 50 of 50, so the
paired difference is exactly zero and only online gating is slightly negative;
the clean column still lacks seeds, so we withhold a verdict on harmlessness.
In the corrupted cells the four score sources overlap within one standard
deviation, so the conclusion for this setting reaches only as far as
sign-gating working and beating its controls, and we do not claim that Flirds
is better than the other score sources here. The reason there is no
gradient-noise cell is given in Appendix~B.6.

Magnitude-weighted gating, a policy that adds to the exclusion a weighting of
the remaining clients in proportion to the size of their positive accumulated
contribution, was checked on two CNN partitions and two datasets under the
prior condition that it would be promoted to a main result only if the
corrupted mean and the clean false firing improved together. For Flirds the
condition is met in no cell, so the main policy remains sign-gating. The gain
appears only for FedIF under gradient noise, where the sign gate fails to fire
(CIFAR-10 $+.12$, MNIST $+.020$ to $+.026$), because the magnitude of the
first-order score still ranks the corrupted clients low. We report this as a
counterexample showing that a first-order score can be recovered by changing
the policy (the table and the full verdict are in Appendix~G.3).

Finally, the removal curve actually removes clients in the order of each
method's contribution ranking and retrains from scratch, checking the
downstream consequence of the ranking with a method-independent yardstick. On
the LLM side (five-domain non-IID; because the same validation set is used as
the yardstick as in valuation, this is not a fully independent check),
worst-first removal lowers the validation loss ($+0.0067$ to $+0.0076$) and
best-first raises it ($-0.0084$ to $-0.0016$ over the two corrupted threats),

\subsection{Cost}
\label{sec:cost}

\textbf{Summary.} The dominant heavy computation of Flirds is one HVP per
round, whereas exhaustive enumeration of the in-run Shapley grows
exponentially in the cohort size. The measured ratio varies widely with the
cohort (78.3$\times$ at cohort 10 in the CNN main setting, 4.9$\times$ at
cohort 5 in the LLM main setting), and for very small cohorts exhaustive
enumeration can be cheaper. The LLM measurements are still preliminary, so
firm cost claims are confined to the auxiliary settings.

\textbf{Operation-count model.} The dominant operation counts accumulated over
rounds close analytically and independently of hardware. Flirds needs one HVP
per round, independent of the cohort size; Flirds-1st needs one validation
gradient; singleton utility needs $1{+}|P_r|$ forwards; and the in-run Shapley
needs $2^{|P_r|}$ forwards. The product of these counts with measured per-op
costs (fp32 on B200: forward 1.60s, HVP 10.36s, HVP/forward $\approx 6.5$)
reproduces the measured wall-clock (Table~\ref{tab:opcount}). Aggregating the
updates and the per-client
inner products are linear in $|P_r|$, so calling the cost constant refers to
the number of dominant heavy operations and not to the total amount of
computation.

single-digit percentage while exhaustive enumeration costs more than the
training. This 78.3$\times$ is smaller than the ratio predicted by the

cohort; it does not transfer absolute ratios between tracks whose per-op unit
costs differ. That the Monte-Carlo reconstruction methods (GTG-Shapley, FedSV,

is because they reconstruct and evaluate coalition models every round, and
since
this depends on the sample-count setting we do not read it as an intrinsic
lower bound of those methods.

relative to client training time (mean $10{,}166$s) Flirds is 39\% while
exhaustive enumeration is 189\%. In this setting the advantage of Flirds is
not that it is overwhelmingly cheaper than exhaustive enumeration but that it
is cheaper than the training, and we do not use these numbers for firm cost
claims until the runs complete.

5 a round takes $2^5{=}32$ forwards, so exhaustive enumeration is still
affordable (the measured ratio of about 5$\times$ in the IID-clean Alpaca

about 159$\times$ Flirds (Appendix~E.2). Conversely, if participation per
round is very small (say 2 clients, $2^2{=}4$ forwards, less than one HVP at
about 6.5 forwards), exhaustive enumeration is cheaper than Flirds. The cost
advantage of Flirds thus belongs to settings with enough participation to make
exhaustive enumeration exponentially expensive; and even outside such
settings, Flirds-1st (one gradient per round) was the cheapest in every
setting we report and in the operation-count model. We do not extend this to a
general law over all hardware and validation sets. The retraining-based
Shapley costs about nine times the in-run Shapley in the IID-clean Alpaca
setting ($30{,}817\pm299$s vs.\ $3{,}528\pm101$s; $2^5$ subsets $\times$
$R{=}30$ retraining rounds). The final cost table also reports end-to-end time
including training and the valuation overhead ratio.

\subsection{Ablation: The Second-Order Curvature Term}
\label{sec:ablation}

\textbf{Summary.} The present evidence is not that the second-order term is
needed in every regime, but that it defends against the failure of the
first-order approximation in specific regimes, namely sparse participation and
strong curvature effects such as gradient noise.

This is the contrast with the Flirds-1st of
Section~\ref{sec:estimator}. On the fidelity axis, the participation sweep of
the $N{=}10$ grid shows the effect of sparse participation. Under label-flip
with 2/10 participation per round, the first-order approximation collapses
(Flirds $0.891\pm.154$ vs.\ Flirds-1st $0.305\pm.453$), while under full
participation the two are close ($0.993$ vs.\ $0.940$). In the LLM main
setting, where each client participates often enough (5/50 with $R{=}200$,
about 20 times), the first order also holds at $1.000$. This contrast varies
the participation count and the setting together, however, so the causal
effect of the participation count alone remains a hypothesis. The gap in the
gradient-noise discriminating cell reproduces in the same direction on three
axes, fidelity in the main setting (Table~\ref{tab:cnn-fidelity}), the
intervention (Section~\ref{sec:intervention}), and detection (Appendix~F), and
it is the same along the dataset axis (MNIST: fidelity $.923$ vs.\ $.313$,
intervention $.9773$ vs.\ $.9091$, AUROC $.999$ vs.\ $.513$) and the scale
axis ($N{=}10$ grid: AUROC $1.000$ vs.\ $.208$ to $.625$, removal separation
$+0.272$ vs.\ $-0.021$). This cell is not an artifact of one particular
setting.

\section{Limitations}
\label{sec:limitations}

\textbf{The validation set as the judge of value.} The most fundamental
premise is that the server's validation set is the judge of value. Since the
utility of the game is the validation loss, the composition of the validation
set determines the meaning of every value. If the premise that the validation
set is fair to all clients breaks down, through the under-representation of a
particular group or task, then clients who are useful to that group are
systematically undervalued; and contributions outside the distribution that
the validation set covers are invisible to the game altogether, so they cannot
be evaluated at all. For the same reason, the honest answer of the game to an
attack that actually lowers the validation loss (the example at the beginning
of Appendix~F) is that it contributed, and catching such an attack is the job
of dedicated detection rather than of contribution measurement. Securing a
representative validation set is itself difficult in a non-IID federation, so
the composition and the auditing of the validation set remain the
responsibility of whoever uses the method.

\textbf{What the values mean, and the ceiling on validation.} The numbers
Flirds produces are not the intrinsic value of data but a conditional
attribution of the validation-loss decrease of one realized trajectory. The
lottery of which client was drawn in which round is not corrected for, the
Shapley axioms are properties inside the frozen round game, and the
axiomatization of trajectory-specific utilities is an open problem. The sum of
the closed forms is efficiency within the second-order surrogate game, so a
gap to the realized improvement (the Taylor residual) remains in every round;
its constants are not tightly estimable for large models
(Section~\ref{sec:theory}), and the $C^3$ assumption on which the bound rests
does not hold on the ReLU CNN track (Appendix~A.4). The scores therefore
cannot be used as a payment rule that substitutes them directly for monetary
compensation (residual allocation and strategic reporting are not treated).
Validation, too, has a ceiling. The retraining-based Shapley is not computable
in principle at the scale of the main settings, so the relation between the
two games is an empirical rather than a theoretical question and the answer
stops at a conditional characterization over small $N$; in the IID-clean
regime, where no genuine signal exists, the target ranking itself does not
reproduce across seeds, so there is nothing to measure (Appendix~D.2); and
some tables of the LLM main setting are still short of three seeds and
therefore preliminary.

\textbf{System and operational assumptions that fix the scope.} The closed
form and the realized-trajectory semantics depend on synchronous FedAvg in
which individual updates are observed and aggregated additively, on a
stateless server without momentum, and on stateless clients (Appendix~A.7).
Server momentum and Adam break these semantics, and in environments such as
Secure Aggregation \citep{bonawitz2017practical}, where only the sum is
exposed, the per-client inner products cannot be computed. On the LLM track,
the mismatch between the token-mean loss and the FedAvg weights means that the
client reading of a per-sample sum does not transfer (Appendix~A.5), and the
game and the HVP are defined in the coordinates of the LoRA factors
(Appendix~A.8). The threat model is static: corruption is fixed in advance, we
do not treat adaptive attacks that know the scoring scheme or
clean-preserving poisoning, and the threat axes of the two tracks are not
fully identical (Appendix~B.6). The experiments are at a scale of $N \le 100$
with 5 to 10\% participation and on top of a deterministic stack
(Appendix~B.4), and operating contribution-based exclusion in practice would
require a conservative threshold that accounts for the clean false firing of
Section~\ref{sec:intervention}, an appeal and reinstatement procedure, and
separate validation of the cumulative effects of exclusion.

\section{Conclusion}
\label{sec:conclusion}

Flirds turns the validation-loss game of an observed FedAvg round, with the
actual aggregation weights held fixed, into a second-order Taylor surrogate,
and closes the computation of its Shapley value with one HVP per round and one
inner product per client. It removes coalition re-evaluation while keeping the
game being computed, the in-run Shapley, and the approximation residual
separable and auditable.

The experiments leave three insights. First, the in-run Shapley and the
retraining-based Shapley are not two interchangeable ways of computing one
quantity but two games that ask different questions, and their agreement is a
conditional fact that holds when corruption creates a genuine signal; in
regimes without a signal there is nothing to measure in the first place.
Second, the choice of game surfaces in downstream performance. The zero
semantics that gives exactly zero to a zero-update client decided whether
sign-gating lived or died, and which Shapley value one scores against changed
the ordering of methods (the confirmation on the detection axis is in
Appendix~F). Third, both the necessity of the second-order curvature term and
the cost advantage are conditional: the former belongs to regimes with sparse
participation or strong curvature effects, the latter to large cohorts where
exhaustive enumeration is exponentially expensive. The scope of these claims
follows Section~\ref{sec:limitations}, and until the unfinished tables of the
LLM main setting are complete we make no firm claim about that setting and no
associated claim of being first. Future work includes extending the game to
stateful servers and Secure Aggregation, axiomatizing trajectory-specific
utilities, and designing payment mechanisms that address the Taylor residual,
participation opportunity, and strategic behavior.
