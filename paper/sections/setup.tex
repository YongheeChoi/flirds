\section{Problem Setup: Two Exact Ground Truths on One Trajectory}
\label{sec:setup}

\paragraph{Federated fine-tuning.}
$N$ clients hold instruction-tuning datasets $D_1,\dots,D_N$ with sizes $n_k$.
FedAvg \citep{mcmahan2017fedavg} runs rounds $r=1,\dots,R$; in round $r$ a cohort
$P_r \subseteq [N]$ trains locally from the broadcast iterate $w^r$ and returns
updates $\Delta w_k^r$ (in our LLM experiments, LoRA adapter parameters
\citep{hu2022lora}; local training is plain SGD, momentum $0$,
\S\ref{sec:protocol}). The server aggregates with \emph{fixed participant
weights}
\begin{equation}
w^{r+1} = w^r + \sum_{k \in P_r} p_k^r\, \Delta w_k^r,
\qquad p_k^r = \frac{n_k}{\sum_{j \in P_r} n_j}.
\label{eq:fedavg}
\end{equation}
The server also holds a validation set $\val$ and can evaluate
$\ell(w) := \ell(w;\val)$, the (sum) validation loss.

\paragraph{Sign convention.}
Throughout the paper, contribution values are presented so that
\emph{larger $\phi$ means more beneficial} (a client whose updates reduce
validation loss receives positive value). \pending{D-3: internal code convention

\subsection{Ground truth (b): the exact in-run game}
\label{sec:oracle-b}

Fix the realized trajectory $\{w^r, \{\Delta w_k^r\}_{k\in P_r}\}_{r=1}^R$
(``frozen logs''). For each round define the coalition utility
\begin{equation}
u_r(S) \;=\; \ell(w^r) \;-\; \ell\Big(w^r + \textstyle\sum_{k \in S} p_k^r\, \Delta w_k^r\Big),
\qquad S \subseteq P_r,
\label{eq:inrun-utility}
\end{equation}
i.e., the validation-loss \emph{reduction} achieved by aggregating exactly the
updates of $S$, with the \emph{same fixed weights} $p_k^r$ as the run itself
(weights are \emph{not} renormalized within $S$; \S\ref{sec:theory} shows this
choice is forced, not cosmetic). The in-run oracle value is the exact Shapley
value of each round game, summed:
\begin{equation}
\phi_k^{(b)} \;=\; \sum_{r\,:\,k \in P_r} \mathrm{Sh}_k\big(u_r\big),
\end{equation}
computed by full $2^{|P_r|}$ enumeration per round (no sampling error). By
telescoping, the grand-coalition utility equals the realized total loss change,
$\sum_r u_r(P_r) = \ell(w^0) - \ell(w^R)$, so the values distribute exactly what
the run achieved (efficiency).

\subsection{Ground truth (a): the exact retrain game}
\label{sec:oracle-a}

The classical, method-neutral target: for $S \subseteq [N]$,
$\aOracle(S)$ is the final validation loss of a complete FL run using only the
clients in $S$ (same protocol, same seeds), and $\phi^{(a)}$ is the exact Shapley
value over all $2^N$ retrains. Oracle (a) answers a \emph{counterfactual}
question (``what if only $S$ had participated?''), oracle (b) a \emph{realized}
one (``how did the run that actually happened distribute its progress?'').
They are different games; neither is wrong. Their empirical relationship---and
which one a valuation method should target---is itself a measurement question
(\S\ref{sec:results-dual}, \todo{judge-cell E1}).

\paragraph{Why exactness forces fp32.}
Coalition utilities are loss differences of order $10^{-3}$ (measured
coalition gaps $0.005$--$0.02$); bf16 resolution near our loss values is
$\sim 8\times 10^{-3}$, so under bf16 the utilities themselves are below the
representable difference floor and retrain-oracle comparisons fail in our runs
\verify{06-07 bf16-failure note; canonical rerun pending (R2/E1)}. All utility
evaluations, HVPs, and inner products are therefore computed in fp32
(\S\ref{sec:protocol}).
